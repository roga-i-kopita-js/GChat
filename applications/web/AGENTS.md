# GChat Web

Общие правила — в корневом AGENTS.md. Перед изменениями читайте docs/web/README.md и контракт владельца backend API.

- Используйте React, TypeScript, TanStack Query, Zod и браузерные API, уже подключённые в package.json. Версии и команды берите из манифеста и lock-файла.
- Один профиль браузера имеет одну сохранённую сессию и device binding. Владелец WSS/медиа выбирается Web Locks; вкладки не должны конкурировать за refresh token или выбранный звонок.
- Не заменяйте серверную модель звонка локальным состоянием. Учитывайте version, sequence, negotiation_id и неизвестный результат команд. Не повторяйте call.create автоматически.
- Не показывайте токены, TURN credentials, SDP, ICE-адреса и полные сообщения в диагностике. Не сохраняйте их в артефактах рабочих пользовательских сессий.
- Интерфейс строится вокруг групп и людей. Диагностика отделена от основных пользовательских сценариев. Учитывайте клавиатуру, узкий экран и браузерные ограничения микрофона/autoplay.
- Форматирование и линтинг используют общие Prettier/Oxlint из корня workspace. Проверка: `pnpm --filter @gchat/web lint`; исправление: `pnpm --filter @gchat/web lint:fix`. Не дублируйте конфигурацию и версии инструментов в приложении.
- После изменения выполните typecheck, build и относящиеся тесты. Аудио E2E запускайте только на выделенном стенде из README; скрипт сбрасывает его звонки.

- Дерево маршрутов и проверки доступа находятся в `src/app`; правила URL и границы разделов — в [веб-контракте](../../docs/web/README.md#маршрутизация-и-структура-исходников). Используйте Link/NavLink для внутренних переходов. Данные загружаются через TanStack Query.
- Код разделов хранится в `src/features/auth`, `src/features/calls`, `src/features/administration`; общие компоненты и транспорт — в `src/shared`, без импортов разделов из `shared`. Не привязывайте жизненный цикл WSS и медиа к монтированию страницы: CallsProvider остаётся выше Routes, входящий вызов доступен из любого раздела.

- Дизайн в первую очередь мобильный: базовые стили для телефона, расширения для настольного экрана. Соблюдайте [правила плотности и контрольные размеры](../../docs/design/README.md#мобильный-приоритет-веб-интерфейса); проверяйте основные экраны и модальные окна на узкой ширине, не уменьшая области нажатия.
