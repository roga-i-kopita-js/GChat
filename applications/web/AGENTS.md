# GChat Web

Общие правила — в корневом AGENTS.md. Перед изменениями читайте docs/web/README.md и контракт владельца backend API.

- Используйте React, TypeScript, Zod и существующие браузерные API. Целевая архитектура — [device](../../docs/web/device-api.md) и [React Router Data mode](../../docs/web/data-flow.md). TanStack Query удалён: серверные данные страниц загружайте через loaders/actions React Router, живые данные — через профильные runtime-модели. Не возвращайте Query hooks/provider или второй кеш этих данных. Версии и команды берите из манифеста и lock-файла.
- Один профиль браузера имеет одну сохранённую сессию и device binding. Владелец WSS/медиа выбирается Web Locks; вкладки не должны конкурировать за refresh token или выбранный звонок.
- Не заменяйте серверную модель звонка локальным состоянием. Учитывайте version, sequence, negotiation_id и неизвестный результат команд. Не повторяйте call.create автоматически.
- Не показывайте токены, TURN credentials, SDP, ICE-адреса и полные сообщения в диагностике. Не сохраняйте их в артефактах рабочих пользовательских сессий.
- Интерфейс строится вокруг групп и людей. Диагностика отделена от основных пользовательских сценариев. Учитывайте клавиатуру, узкий экран и браузерные ограничения микрофона/autoplay.
- Форматирование и линтинг используют общие Prettier/Oxlint из корня workspace. Проверка: `pnpm --filter @gchat/web lint`; исправление: `pnpm --filter @gchat/web lint:fix`. Не дублируйте конфигурацию и версии инструментов в приложении.
- После изменения выполните typecheck, build и относящиеся тесты. Аудио E2E запускайте только на выделенном стенде из README; скрипт сбрасывает его звонки.

- Дерево маршрутов, loaders/actions и проверки доступа находятся в `src/app`/профильных features; правила URL — в [веб-контракте](../../docs/web/README.md#маршрутизация-и-структура-исходников). Bootstrap передаёт маршруты через публичную фабрику device, навигационный адаптер владеет одним router. Device в loaders/actions берите из типизированного контекста React Router через context.get(deviceContext); не импортируйте глобальную сессию/SDK и не замыкайте device в фабрике маршрутов. Защищённые маршруты, включая resource/fetcher, помещайте под sessionMiddleware; пользователя в loaders/actions берите из userContext. Если device нужен компоненту, возвращайте его через loaderData. Используйте Link/NavLink. Данные страницы принадлежат loaderData, live-данные — runtime; не синхронизируйте их копии эффектами.
- Фичи не импортируют embedded, raw native plugin или платформенные адаптеры. HTTP-клиент передаётся в device при создании; native HTTP выполняется сетевым стеком оболочки. Команды и события вызываются через типизированные сервисы device, по принятой спецификации.
- Код разделов хранится в `src/features/auth`, `src/features/calls`, `src/features/administration`; общие компоненты и транспорт — в `src/shared`, без импортов разделов из `shared`. Не привязывайте жизненный цикл WSS и медиа к монтированию страницы: CallsProvider остаётся выше Routes, входящий вызов доступен из любого раздела.

- Дизайн в первую очередь мобильный: базовые стили для телефона, расширения для настольного экрана. Соблюдайте [правила плотности и контрольные размеры](../../docs/design/README.md#мобильный-приоритет-веб-интерфейса); проверяйте основные экраны и модальные окна на узкой ширине, не уменьшая области нажатия.

- UI kit в `src/shared/ui` следует [контракту общей оболочки и токенов](../../docs/web/README.md#общая-оболочка-и-ui-kit): один примитив на файл, `index.ts` только экспортирует. Доменным компонентам и зависимостям место в features/app. Визуальные параметры берите из общей системы токенов; не добавляйте локальные числовые значения шрифтов, отступов, размеров и радиусов вместо существующей шкалы. Исключения для CSS queries и измеренных координат описаны в контракте.
