# Ручная приёмка GChat iOS на физических iPhone

Это план приёмки звонковой интеграции, а не отчёт об её выполнении. Нативная оболочка и bridge реализованы; отдельный [CallKit harness](CallHarness/README.md) проверяет движок до подключения к основной оболочке. Реализованные исходники и успешная сборка не означают прохождения физических сценариев. Неисполненные сценарии имеют статус `not_run`; отсутствие реализации, устройства или APNs credentials фиксируется как `blocked`, а не как успешная проверка.

Архитектура и границы ответственности — в [D008](../../docs/architecture/decisions/D008-capacitor-bridge.md). Ожидаемое серверное поведение принадлежит [Auth](../../docs/backend/modules/auth.md), [DirectCalls](../../docs/backend/modules/direct-calls/README.md), [Signaling](../../docs/backend/modules/signaling.md), [Devices](../../docs/backend/modules/devices.md) и [Push](../../docs/backend/modules/push.md). При расхождении результата с контрактом записать дефект; не менять ожидаемое поведение по факту текущей реализации.

Ручные проверки выполняются только на физических iPhone. Загрузка Web, bridge, авторизация, протокольные гонки и остальные проверки без обязательной физической оценки вынесены в [план автоматизации](automated-tests.md). В Simulator эти сценарии выполняются автоматически; ручного Simulator-прогона нет.

## Подготовка и матрица

- Изолированный backend с PostgreSQL, TURN, доступным HTTPS и тестовыми аккаунтами A/B с правом звонить друг другу; отдельный пользователь C для смены аккаунта. Подготовка инфраструктуры — по [E2E README](../../tests/e2e/README.md), пользовательские сессии не использовать.
- Основной Web размещён на `/apps/client`, assets — на `/apps/static/:filename`; отдельное стартовое Web-приложение включено в native-сборку. Public origin задан в env. Для проверок Origin нужен отдельный запрещённый origin тестовой страницы.
- Зафиксировать native build, commit backend, Web build, bridge version, commit/checksum libwebrtc, серверные таймауты и среду APNs. Использовать реальные значения окружения, а не менять ожидания таймаутов на глаз.
- Два физических iPhone: один с iOS 16.x, другой с актуальной поддерживаемой iOS. Записать модели и точные версии ОС. Все сценарии ниже требуют физического iPhone; повторить на обоих. Для звонков использовать Web ↔ iOS в обоих направлениях и iOS ↔ iOS. Для сетевых сценариев нужны разные сети, Wi-Fi и мобильная сеть; для аудио — Bluetooth-гарнитура и возможность обычного телефонного звонка.
- Gate 1 проверяется без APNs: нативный harness с CallKit и звонком, начатым в foreground. Gate 2 требует APNs credentials, PushKit/CallKit и действительной регистрации устройства; публичная приёмка дополнительно использует production APNs и подписанную сборку TestFlight.
- Для воспроизводимых отказов подготовить тестовый proxy/transport fixture: задержка или потеря ответа, временный отказ backend, ошибка записи/чтения хранилища. Это инструменты выделенного тестового стенда, а не новые production endpoints. Без нужного инструмента сценарий отмечается `blocked`.

Перед каждым сценарием восстановить указанные предусловия. Записывать результат отдельно для каждой ОС, направления звонка и варианта отказа; один успешный вариант не закрывает остальные.

## C: native call engine и CallKit — Gate 1

Перед каждым прогоном убедиться, что оба участника авторизованы, свободны и доступны по WSS. APNs не требуется: входящий можно получить по открытому WSS или начать вызов с iPhone. Прогнать базовый звонок Web → iOS, iOS → Web и iOS → iOS; на обоих iPhone повторить роль проверяемой стороны.

| ID  | Где    | Шаги                                                                                                                                                                    | Ожидаемый результат                                                                                                                                                                                                                                            |
| --- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C01 | iPhone | Создать и принять звонок между разными сетями. Участники по очереди произносят контрольные фразы; проверить безопасные агрегированные данные выбранного ICE-маршрута.   | Двусторонняя слышимость; выбран TURN relay, `call.connected` отправляется после фактического WebRTC connected, backend достигает `active`. Наличие WS-соединения не считается доказательством аудио.                                                           |
| C02 | iPhone | По отдельности проверить отклонение, отмену инициатором, отсутствие ответа и завершение каждой стороной.                                                                | У обоих участников корректный конечный результат по DirectCalls; системный UI и аудио закрываются, занятость освобождена, можно начать новый звонок. Таймауты соответствуют конфигурации стенда.                                                               |
| C03 | iPhone | Во время разговора проверить mute/unmute, доступные аудиомаршруты, подключение и отключение Bluetooth-гарнитуры.                                                        | Mute не завершает звонок. При реальной потере соединения применяется recovery.                                                     |
| C04 | iPhone | Начать разговор, свернуть приложение, заблокировать экран; продолжить разговор через несколько периодов call.ping. Вернуться в приложение и завершить из системного UI. | Двусторонняя слышимость и native-пинги продолжаются, нет ложного recovery из-за остановки JS. Web восстанавливает снимок; завершение освобождает микрофон и системный UI.                                                                                      |
| C05 | iPhone | Принять обычный телефонный звонок во время GChat; завершить его. Прогнать короткое и превышающее серверное окно восстановления прерывание.                              | Активация/деактивация CallKit-аудиосессии корректна; нет конфликтующих владельцев микрофона. | C06 | iPhone | Кратко отключить сеть, восстановить до дедлайна; отдельно переключить Wi-Fi ↔ мобильную сеть.                                                                           | Native переподключается, регистрирует прежний device binding, получает актуальный state и восстанавливает медиа. | C07 | iPhone | Отключить сеть дольше серверного срока восстановления или сделать TURN недоступным; восстановить сеть после завершения.                                                 | Нет вечного `connecting`/`active`; конечное состояние и освобождение занятости соответствуют DirectCalls. Позднее подключение не возрождает завершённый звонок; можно создать новый.                                                                           |

Дополнительный вариант C03 для harness: проверить системный ползунок громкости и аппаратные кнопки по [критериям управления громкостью](../../docs/ios/call-volume.md#критерии-приёмки), включая оба встроенных динамика и заблокированный экран.

Выбор устройства в harness проверяется по [критериям маршрутизации UI](../../docs/ios/audio-devices.md#критерии-приёмки), включая доступность системного списка, подключение/отключение гарнитуры и соответствие фактическому выходу.

## P: PushKit, CallKit и жизненный цикл устройства — Gate 2

Не имитировать настоящую доставку только прямым вызовом обработчика. Инъекция повторного payload допустима для проверки дедупликации, но отдельно от end-to-end APNs-проверки. Холодный старт ниже означает завершение процесса системой/тестовым инструментом; пользовательский force quit проверяется отдельно и не приравнивается к гарантированной доставке.

| ID  | Где    | Шаги                                                                                                                                                                                                | Ожидаемый результат                                                                                                                                                                                                                                                                                              |
| --- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P01 | iPhone | Послать реальный входящий через APNs при открытом приложении, в фоне и на lock screen; ответить и завершить.                                                                                        | Один системный входящий на call_id, обязательная CallKit-обработка не ждёт сети. После серверного принятия — двустороннее аудио и корректное завершение.                                                                                                                                                         |
| P02 | iPhone | Сохранить сессию, завершить процесс без force quit пользователя, дождаться истечения access token и отправить настоящий VoIP push.                                                                  | Native восстанавливает сессию, выполняет refresh/WSS/device registration и принимает звонок без запуска WebView. Нет ожидания Face ID; системная обработка push не блокируется сетевой авторизацией.                                                                                                             |
| P03 | iPhone | Одновременно доставить один вызов через WSS и APNs. Затем инъецировать повтор того же push.                                                                                                         | Один звонок и один комплект ресурсов; нет повторного медиа/принятия. Обязательства PushKit/CallKit соблюдаются при дубликате. Инъекция не засчитывается как повторная реальная APNs-доставка.                                                                                                                    |
| P04 | iPhone | Отменить вызов до доставки задержанного push; отдельно доставить payload завершённого/просроченного вызова.                                                                                         | Системная обработка выполняется по Push-контракту, устаревший вызов закрывается после сверки; нет зависшего системного входящего и нового серверного звонка.                                                                                                                                                     |
| P05 | iPhone | На системном входящем одновременно нажать «Ответить» и отменить вызов у инициатора. Повторить с двумя устройствами получателя, отвечающими одновременно.                                            | Сервер выбирает один допустимый исход/одно устройство-победитель. Проигравший UI закрывается, нет второго медиа или зависшего CallKit-вызова.                                                                                                                                                                    |
| P06 | iPhone | Доставить push, но блокировать refresh/WSS до истечения ringing; отдельно использовать уже отозванную сессию.                                                                                       | Нет принятия без серверной авторизации и бесконечного звонка. CallKit получает обязательную обработку, затем UI закрывается; временная ошибка не удаляет сессию как недействительную.                                                                                                                            |
| P07 | iPhone | После входа перезагрузить iPhone. Проверить недоступность контекста до первой разблокировки; затем разблокировать один раз, снова заблокировать и отправить push.                                   | До первой разблокировки недоступность Keychain не удаляет сессию; доставку в этом состоянии не считать гарантированной. | P08 | iPhone | Отказать в микрофоне; отдельно проверить отключённые пользовательские уведомления, Focus/энергосбережение и force quit. ## Результат прогона и выпуск

Статусы: `not_run`, `pass`, `fail`, `blocked`. Для каждого варианта сценария заполнить:

| Поле           | Что записать                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Прогон         | Дата/время с часовым поясом, проверяющий, ID сценария и вариант                                                                 |
| Сборки         | Native/Web/backend/bridge версии, libwebrtc commit/checksum                                                                     |
| Среда          | Модель физического iPhone и версия iOS, направления звонка, сети, APNs environment, таймауты                                    |
| Результат      | Статус, наблюдаемое поведение и отличие от ожидаемого                                                                           |
| Доказательства | Безопасные screenshots, время события, call_id/request_id, выбранный тип ICE-маршрута без адресов/credentials, ссылка на дефект |
| Блокер         | Чего не хватает для выполнения и какой сценарий повторить после устранения                                                      |

Проверка успешна только при подтверждении ожидаемого результата обоими участниками и серверным состоянием, где это требуется. `200` APNs, открытый экран CallKit и `active` без проверки слышимости не доказывают рабочий звонок. После проверки завершить тестовые звонки, убедиться в освобождении ресурсов и восстановить настройки устройства.

Автоматические B/A/C10 выполняются по отдельному плану и не требуют ручного повторения на Simulator или iPhone. Gate 1 требует ручных C01–C07 на обоих физических устройствах и автоматического C10; C08/C09 проверяются позже с полным WebView в интеграционной приёмке. Gate 2 требует P01–P09 на физических устройствах с реальным APNs для сценариев доставки. До публичного App Store релиза закрыть обязательное автоматическое покрытие, ручные сценарии на обоих устройствах и production APNs/TestFlight-проверку. Если среда/сборка не позволяет проверить отдельный случай, он остаётся `blocked`, а gate не объявляется пройденным. Для исследовательских ограничений ОС в P07/P08 фиксируется поведение, указанное в ожидаемом результате, а не требование гарантированной доставки.
