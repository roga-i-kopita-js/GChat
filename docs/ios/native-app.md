# Основное приложение iOS: Web-интерфейс и нативные звонки

## Назначение и границы

Объём явно подтверждён пользователем 2026-11-11. Следующий этап после отдельного Audio Test: подключить проверенные DirectCallController, libwebrtc и CallKit к существующей основной оболочке GChat. Пользователь поручил завершить ручные прогоны и перейти к основному приложению с Web-интерфейсом. Прежние результаты остаются частичными; переход к интеграции не означает успешного выполнения пропущенных проверок Gate 1.

Используются существующие [bridge v1](../web/README.md#внутренний-формат-gchat-bridge-v1), [Native Calls](native-calls.md), [device API](../web/device-api.md) и серверные DirectCalls/Signaling. Новые публичные методы, второй WSS и браузерный WebRTC во встроенном режиме не вводятся.

Этот этап даёт основное приложение с выбором сервера, входом, контактами, чатами, настройками и настоящими нативными аудиозвонками. PushKit и пробуждение для нового входящего при закрытом/приостановленном приложении остаются следующим этапом. Уже начатый разговор работает независимо от Web в фоне и при выключенном экране.

## Владение и сессия

- Владелец звонков создаётся оболочкой для выбранного сервера и живёт независимо от WebView/cycleId. Используются её SessionManager, Keychain и единственный SharedWebSocket; отдельный тестовый аккаунт или транспорт Audio Test не переносятся.
- DirectCallController получает нативные сообщения WSS до политики выдачи сообщений Web. Существующая политика продолжает скрывать SDP/ICE и транспортные секреты от Web.
- Владелец привязан к актуальным account/session. Повторный webReady и перезапуск WebContent не создают новый движок, не прекращают разговор и не сбрасывают sequence пингов.
- Logout, инвалидирование сессии и смена сервера завершают местные звонковые ресурсы. Поздние операции предыдущих сессии/сервера не меняют новую сессию.
- Подготовка, активация и деактивация аудио следуют Native Calls. CallKit остаётся владельцем активации; системный reset освобождает локальные ресурсы.

## Web и нативное управление

- В основной сборке с установленным движком getCapabilities возвращает nativeCalls=true. Остальные версии и методы bridge сохраняются.
- placeCall принимает существующий peerId и запускает один исходящий через нативный controller после разрешения микрофона. Команда не повторяет call.create при неизвестном результате; Web получает только существующее подтверждение, состояние приходит событиями.
- При webReady оболочка выдаёт актуальный безопасный callSnapshot текущего cycleId. Далее callStateChanged/callRuntimeChanged обновляют Web. DTO берётся из нативной серверной проекции; микрофон, SDP, ICE, TURN credentials и внутренние ошибки в снимок не добавляются.
- Runtime отражает доступность общего WSS для нативных звонков; muted отражает фактическое локальное состояние. Отсутствие call не означает offline, если авторизованный транспорт готов.
- Сохраняется принятый режим управления host: Web показывает собеседника, состояние и длительность, а native предоставляет ответ/отклонение/завершение и mute.
- В foreground для входящего показывается нативная панель управления. Для исходящего и активного разговора та же панель доступна из компактного элемента поверх основного интерфейса. Панель можно свернуть и продолжить работу с Web; сворачивание не завершает вызов. При завершении панель и элемент управления скрываются.
- Нативные подписи показывают понятные состояния вызова; технические UUID и тестовые поля harness в интерфейс основного приложения не переносятся. Детали собеседника остаются в существующем Web-интерфейсе.
- Разрешение микрофона запрашивается по действию пользователя перед исходящим или ответом. После ожидания permission проверяются прежние call/session; завершённый вызов не принимается запоздало.
- Выбранный Call передаётся существующему владельцу native media для Call lifetime. Окончание звонка освобождает Call lifetime/PiP по действующему device API.

Ползунок громкости и дефект системной кнопки динамика остаются [за рамками текущего скоупа](native-calls.md#отложенные-дефекты-текущего-этапа). Новая основная панель ограничивается управлением жизненным циклом звонка и mute; отложенные контролы в неё не добавляются.

## Сборка и запуск

- Основной target подключает тот же закреплённый XCFramework и общие CallKit/WebRTC-адаптеры, что Audio Test, с требуемыми background modes. SDK и состояние его приёмки не переименовываются в полностью принятые.
- Основной Web собирается в серверном режиме и загружается по существующим /apps/client и /apps/static. HTTPS, проверка сертификата, ограничения origin/навигации и запрет браузерного микрофона сохраняются.
- На доступный iPhone устанавливается основная сборка GChat, использующая собственную основную native-сессию. Запускается локальная HTTPS-среда с Web; legacy Mattermost/Jitsi и рабочие аккаунты не используются.
- Ручная матрица Audio Test завершена текущим поручением. Для реализации выполняются необходимые автоматические проверки и сборки; новые ручные аудиосценарии без отдельного запроса не запускаются.

## Критерии приёмки реализации

1. Основной target собирается с настоящим WebRTC для Simulator и физического iPhone; библиотека корректно встроена и подписана.
2. GChat открывает серверный Web с существующим входом, контактами и чатами, сообщает nativeCalls=true и не запускает браузерный движок звонков.
3. Подтверждённый исходящий из Web передаётся одному нативному controller; native UI предоставляет ответ/отклонение/завершение и mute.
4. CallSnapshot и обновления содержат безопасный актуальный DTO/мьют, сохраняют cycleId, обработку версий и защиту от прежней сессии. Web-ready/WebContent restart не пересоздают активный звонок.
5. Logout/инвалидирование/смена сервера освобождают звонковые ресурсы; завершение вызывает освобождение Call media/PiP.
6. Автоматические регрессии существующего bridge/NativeCore и проверка документации проходят. Непроверенные физические сценарии и PushKit явно остаются непройденными.
