# D006: сессии Auth в PostgreSQL

## Контекст

Аккаунты хранятся в PostgreSQL, текущая реализация сессий и временных результатов refresh — в Redis. При проектировании бэк-офиса это разделение потребовало координировать отключение аккаунта, смену пароля и массовый отзыв между двумя хранилищами. Поздняя запись сессии после отзыва может вернуть старый доступ при повторном включении.

## Решение

Перенести сессии Auth, временные результаты обновления токенов, одноразовые WS-билеты и ограничение их выдачи в PostgreSQL. Согласованный контракт и правила конкурентности принадлежат [Auth](../../backend/modules/auth.md#хранение-сессий-в-postgresql--согласовано-не-реализовано). Смена пароля, отключение и включение выполняются атомарно с отзывом сессий; вход и обновление токенов координируются блокировками строк в той же БД. Последний временный результат обновления хранится прямо в строке сессии, заменяется следующей ротацией и удаляется вместе с сессией; отдельная таблица истории не создаётся.

Это заменяет прежнее решение о хранении сессий и результатов ротации в Redis. Общие правила собственных аккаунтов, JWT и независимых сессий из [D001](D001-accounts-and-sessions.md) сохраняются. Срок WS-билета, одноразовость, Origin и лимит выдачи сохраняются по контракту Auth. После реализации хранение и проверка данных Auth не зависят от Redis; cron-очистка использует Redis через Redlock для координации между процессами. Остальные потребители Redis этим решением не переносятся.

## Последствия

Не нужны `auth_version`, временное отключение при смене пароля и длительные блокировки между PostgreSQL и Redis. Потеря подтверждения COMMIT всё ещё может оставить результат неизвестным; устойчивый журнал операций не добавляется.

Перенос пока не реализован. Потребуются схема и миграции, замена AuthSessions и AuthWsTickets, обновление проверок HTTP/WS и интеграционных тестов. Фоновая очистка истёкших результатов, билетов и окон выдачи согласована через `@nestjs/schedule`, раз в минуту, с Redlock на общий ресурс для координации процессов; SQL-проверки обеспечивают безопасность очистки при потере аренды. Правила пачек и конкурентности принадлежат Auth. Пакет пока не подключён. Согласована схема двух таблиц: `gchat_auth_sessions` со встроенными результатом refresh и счётчиком выдачи, `gchat_auth_ws_tickets` с каскадным удалением по сессии. Поля, ограничения и индексы определены в Auth; SQL-миграции ещё не реализованы. Перенос действующих сессий и совместимость старых форматов не проектируются: продукт ещё не вышел в production.
