# D007: маршрутизация и разделы веб-клиента

Дата: 2026-11-04; уточнение целевой архитектуры — 2026-11-08 по поручению пользователя самостоятельно закрыть детали API device и потока данных.

## Контекст

Адрес должен восстанавливать страницу, выбранную сущность, поиск и пагинацию. Звонок, WSS и медиаресурсы живут дольше страницы. В текущей реализации BrowserRouter выбирает страницу, а Query, локальный runtime и React state одновременно участвуют в загрузке и хранении данных; перенос запросов в loaders требует устранить параллельный кеш.

## Решение

Использовать React Router Data mode с createBrowserRouter, RouterProvider и клиентскими loader/action, сохранив Vite. TanStack Query удалить после переноса последнего потребителя. Framework mode, SSR и файловая генерация маршрутов не нужны для текущего клиента. Версии и команды берутся из манифеста и lock-файла.

Серверные данные страницы проходят через loader → сервис → generated SDK → mapping → loaderData. Изменения административных форм проходят через action и штатную ревалидацию. Звонок, сессия и живые диалоги остаются у долгоживущих runtime; у loader нет независимой изменяемой копии истории/outbox.

Bootstrap передаёт конфигурацию через публичную фабрику device. Навигационный адаптер device создаёт один router, DeviceProvider монтирует RouterProvider; Web, native и уведомления используют тот же экземпляр. Прямого управления реализацией router из bootstrap нет. Shared не импортирует app/features, маршруты и обработчики передаются как зависимости.

Действующие адреса и доступы — в [Web-контракте](../../web/README.md#маршрутизация-и-структура-исходников). Модели страниц, формы и критерии миграции — в [потоке данных](../../web/data-flow.md); публичный API и native-навигация — в [device](../../web/device-api.md). Эти документы владеют подробностями, решение их не дублирует.

## Последствия

У данных страницы один владелец, для живых данных сохраняется профильный runtime. Нет второго WSS или медиадвижка при переходах. Protected loaders/actions проверяют сессию независимо друг от друга, учитывают отмену и смену scope. Несохранённый ввод защищён одним blocker для Web/native/истории.

Основное дерево переведено на Data router, Query удалён. Ленивые модули и вложенная композиция UI определены в [потоке данных](../../web/data-flow.md#ленивые-модули-и-вложенные-маршруты). Миграция считается завершённой после удаления query hooks/provider/зависимости и проверки URL, историй, доступа, форм и непрерывности звонка. SPA fallback сохраняется отдельно от `/api` и `/ws`; физические медиапроверки не заменяются маршрутными тестами.

## Рассмотренные варианты

- BrowserRouter + Query: подходит текущему коду, но оставляет второй механизм получения данных при принятом переходе на loaders.
- Framework mode: потребует изменения сборки и соглашений без необходимого клиенту SSR.
- HashRouter или переключение React state: не требуются при History API и существующем SPA fallback.
