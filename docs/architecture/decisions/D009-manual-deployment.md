# D009: ручной деплой на существующий сервер

Дата: 2026-11-05.

## Контекст

GChat требуется простой воспроизводимый выпуск. Уже есть сервер в Яндекс Cloud; пользователь согласовал использование GitHub Actions для сборки Docker-образа и nginx-конфига с последующей передачей на сервер и запуском приложения. Дополнительные платные сервисы не требуются.

## Решение

Доставка запускается только вручную через `workflow_dispatch` / Run workflow. Пуши, pull requests и теги не выкатывают приложение автоматически. GitHub Actions собирает артефакты и передаёт их на существующий сервер по SSH. В базовом варианте Docker Registry не используется. На сервере загружается готовый образ, отдельно применяются миграции, запускается приложение и проверяется готовность.

Существующие данные и секреты хранятся на сервере отдельно от релиза. Инфраструктура самостоятельного GChat изолирована от legacy Mattermost/Jitsi.

Для более сложных окружений предоставляются готовые Docker-образы всех собственных самостоятельно развёртываемых серверных компонентов GChat. Владелец окружения выбирает способ оркестрации и доставки. Готовые Helm charts и Kubernetes-манифесты в текущий объём не входят. Все Docker-образы собственных компонентов публикуются в GitHub Releases соответствующей версии приложения как скачиваемые архивы, вместе с manifest и контрольными суммами. Для базового деплоя используется та же сборка. Публикация релиза не запускает выкладку автоматически. Состав образов и границы внешних зависимостей описаны в [основном документе](../../operations/deployment.md#поставка-для-сложных-окружений).

## Последствия и границы согласования

Сборка не требует инструментов разработки на сервере и подписки на registry. Сохраняются существующие расходы Яндекс Cloud; бесплатность Actions ограничена включённой квотой. Обновление одного экземпляра приложения допускает обслуживающий перерыв.

Основной документ — [развёртывание GChat](../../operations/deployment.md): он содержит технический проект, критерии приёмки и открытые вопросы. Согласован способ доставки, а не каждая деталь проекта. Статус accepted этой записи не означает, что production-комплект реализован или что draft-детали основного документа приняты. Подробности размещения nginx, TLS и серверного Web требуют уточнения до реализации.
