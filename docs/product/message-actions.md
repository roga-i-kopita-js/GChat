# Действия над сообщениями

Расширение [диалогов 1х1](dialogs.md) и [редактирования](message-editing.md) для backend и Web/PWA. Продуктовое поведение согласовано пользователем 2026-11-14, включая правила пересланных копий. iOS не входит в реализацию этого этапа по [приоритету платформ](requirements.md#текущий-приоритет-платформ). [Технический проект](../backend/modules/dialogs/message-actions.md) согласован и готов к реализации. Исправление преждевременного закрытия существующего меню выполняется независимо по принятому контракту редактирования.

## Подтверждённые требования

Пользователь запросил 2026-11-14:

- Пересылку сообщений с именем исходного автора только при общей группе у исходного автора и конечного получателя. Проверка относится к моменту пересылки; наличие общей группы только у пересылающего с получателем недостаточно.
- Копирование текста сообщения.
- Копирование адреса ссылки, если она присутствует в сообщении.
- Несколько разных реакций одного пользователя на сообщение, полный стандартный набор реакций Telegram.

Ниже закреплено согласованное продуктовое поведение. Оно не означает готовности технического контракта или наличия новых функций в коде.

## Общее меню

По согласованию пользователя 2026-11-15 применяется вариант «Фокус на сообщении»: фон ленты приглушён существующим overlay-токеном GChat; список диалогов, шапка и область ввода остаются без затемнения. Выбранный пузырёк показан внутри компактной группы между капсулой быстрых реакций и карточкой команд. Исходный пузырёк временно скрывается без изменения геометрии ленты; закрытие восстанавливает его. Превью сохраняет оформление своего/чужого текста, стикер, отметку пересылки и цитату ответа; длинный текст ограничен тремя строками. Положение группы привязано к сообщению так, чтобы превью оставалось около исходной позиции; у краёв ленты группа смещается в пересечение видимой области ленты и visual viewport, сохраняя доступ к шапке и вводу. Она больше не обязана целиком находиться над кнопкой или пузырьком. При недостатке высоты содержимое прокручивается внутри группы. Подложка не блокирует системную прокрутку ленты.

Капсула реакций и карточка команд имеют общую ширину. Порядок основных команд: «Ответить», «Копировать текст», «Переслать»; ниже отделённая группа «Редактировать» и «Копировать ссылку». Неприменимые действия скрыты. Подписи слева, привычные иконки справа; области нажатия не меньше 44 CSS px. Меню доступно у своих и чужих сохранённых сообщений; редактирование сохраняет проверку авторства и действующие права. Несохранённые сообщения/outbox не пересылаются и не получают реакций. Сохраняются текущая палитра «Северное сияние», поверхности, акцент, overlay и тени из общих токенов; отдельная цветовая схема не вводится. По уточнению пользователя меню визуально согласуется с текущим Web: команды используют body-типографику и leading общих контролов, карточка — общий радиус, тонкую границу и малую тень, иконки действий — общий акцент. Превью повторяет пузырёк переписки, включая отметку доставки/прочтения, без дополнительной тени.

Полный каталог заменяет список команд прокручиваемой сеткой в той же группе, сохраняя превью и доступную высоту. Вместо капсулы показаны «Назад» и «Готово». Назад/Escape возвращает команды и фокус к кнопке «Все реакции»; «Готово» закрывает меню с возвратом фокуса к источнику. По последнему уточнению пользователя выбор или снятие реакции закрывает всё меню, включая полный каталог, после подтверждённого успеха. Для добавления следующего emoji пользователь открывает меню заново; уже выбранные реакции сохраняются. Ошибка оставляет меню открытым и показывает доступное сообщение без неподтверждённого успеха.

Длительное нажатие на телефоне, контекстное меню/действие при наведении на ПК и ContextMenu/Shift+F10 с клавиатуры открывают один интерфейс. Отпускание исходного пальца не закрывает меню; следующий тап по действию срабатывает. При отмене на сенсорном экране меню закрывается завершённым тапом снаружи: начало касания, отпускание исходного долгого нажатия, прокрутка ленты или меню, уход указателя, потеря фокуса и повторное нажатие кнопки действий его не закрывают. Жест с перемещением более 8 CSS px либо отменённый pointer не считается тапом. С клавиатуры сохраняется отмена по Escape; Tab перемещает фокус без закрытия. Выбор ответа, редактирования или пересылки переводит в соответствующий интерфейс; смена диалога/сессии и потеря доступа завершают меню. Изменение видимой области при скрытии клавиатуры и прокрутка сохраняют меню и корректируют его положение; уход исходного сообщения из виртуализированной ленты сам по себе не закрывает уже открытое меню. Сохраняются выделение текста, системная прокрутка ленты, доступные подписи, области нажатия от 44 CSS px, токены GChat и правила фокуса принятого интерфейса редактирования.

## Копирование

«Копировать текст» переносит в системный буфер весь текст без имени автора, времени, статусов и отметки о пересылке. Пробелы, Unicode и переносы сохраняются. У стикера действие отсутствует.

«Копировать ссылку» копирует адрес абсолютной HTTP/HTTPS-ссылки в тексте. При одной ссылке копируется её адрес; при нескольких разных адресах открывается список для выбора одного. Порядок соответствует тексту, повторяющиеся адреса объединяются. Переход по ссылке и сетевой запрос для её проверки не выполняются. Остальные URI-схемы и строки без явной схемы в первый этап не входят. Правила распознавания границ URL и пунктуации закреплены в клиентском техническом контракте.

Запись в буфер вызывается непосредственно пользовательским действием. После успеха меню закрывается с возвратом фокуса к источнику, а над лентой на три секунды появляется доступное status-уведомление «Скопировано». При отказе браузера меню остаётся открытым и показывает ошибку с возможностью выделить и скопировать значение вручную. Текст сообщения не передаётся на сервер ради копирования. Чтение истории должно быть разрешено текущему пользователю; после обнаруженной потери доступа действия с содержимым недоступны.

## Пересылка

Первый этап: одно сохранённое текстовое сообщение или стикер одному выбранному собеседнику. Выбор показывает доступные диалоги и контакты, включая человека без существующего диалога. Поиск в этом окне фильтрует получателей, а не историю сообщений. Отдельное подтверждение показывает получателя и содержимое; до нажатия «Переслать» сообщение не отправляется. Отмена сохраняет исходную переписку, позицию и обычные черновики. Массовый выбор сообщений, несколько получателей за одну операцию и комментарий к пересылке в первый этап не входят.

Сервер повторно проверяет чтение источника и право отправки выбранному получателю. Клиент передаёт ссылку на исходное сохранённое сообщение, а не доверенные текст или имя автора. Проверка версии источника не позволяет незаметно переслать текст, изменившийся после предпросмотра: пользователь получает актуальное содержимое и подтверждает его заново.

Результат — самостоятельное новое сообщение от пересылающего, с новым ID, временем, sequence, обычным прочтением, превью и уведомлением. Содержимое фиксируется на момент подтверждённой серверной операции. Последующие правки исходника не меняют пересланную копию. Реакции и статусы исходника не копируются. Повтор запроса с тем же идентификатором операции не создаёт дубль; при неизвестном результате клиент сначала выясняет результат, не создавая новую отправку автоматически.

Над содержимым всегда показывается «Переслано». Имя исходного автора добавляется только при наличии хотя бы одной общей группы у него и конечного получателя в момент операции; принадлежность к группе проверяет backend. Административная роль не обходит это условие. Если общей группы нет, получателю не выдаются также ID автора, профильная ссылка и идентификаторы исходного диалога/сообщения. Авторство не маскируется только средствами CSS.

При повторной пересылке сохраняется первоначальный автор, пока происхождение разрешено передавать. Если одна из предыдущих пересылок скрыла автора, следующая пересылка не восстанавливает его: передаётся только анонимная отметка «Переслано». История цепочки пересылок пользователю не показывается. Уже раскрытое имя остаётся снимком на момент пересылки; последующий выход из группы не обещает удаления сведений с устройств получателя.

Пересланное сообщение не редактируется: для отправки изменённого текста пользователь копирует его в новое обычное сообщение. Это согласованное исключение к правилу редактирования собственного сохранённого текста.

## Реакции

Реакции доступны для своих и чужих сохранённых текстовых сообщений и стикеров без ограничения по возрасту. Для постановки и снятия нужны действующие права отправки в этот диалог. Каждый участник может выбрать несколько разных emoji; один и тот же emoji от одного участника учитывается один раз. Повторное нажатие на свою реакцию снимает только её, выбор другой добавляет её к прежним. Дополнительного лимита меньше размера каталога нет.

Под пузырьком показываются emoji со счётчиком участников; свои выбранные emoji выделены и имеют доступное состояние. По отдельному действию можно посмотреть, кто поставил реакцию. По уточнению пользователя реакции оформляются компактными плашками: видимая высота 28 CSS px, emoji 18 px, счётчик 12 px. Область нажатия сохраняет минимум 44 × 44 px вокруг плашки; выбранное состояние обозначается тонкой границей и мягкой акцентной заливкой самой плашки. Кнопка просмотра участников использует маленькую нейтральную плашку с многоточием. Окно «Реакции» имеет ширину до 300 CSS px и высоту по содержимому; вместо маркированного списка — одна строка на участника с аватаром, именем и его emoji. Несколько реакций одного участника объединяются в его строке. Используются действующие токены GChat. В диалоге 1х1 один emoji имеет счётчик 1 или 2; изменение реакции на одном устройстве появляется на остальных устройствах обоих участников. После офлайна восстанавливается актуальный набор, в том числе у старых сообщений вне последней страницы. Запоздалый ответ не откатывает более новое состояние.

Реакция не создаёт сообщение, не меняет порядок диалогов, время активности и позиции прочтения; отдельный push не отправляется. Правка текста сохраняет реакции. Ошибка изменения не уничтожает прежние реакции и не показывает неподтверждённый успех. Повтор запроса не должен превращать добавление в снятие: серверные команды задают желаемое наличие/отсутствие реакции, а не неидемпотентный toggle. Одновременные изменения разных emoji не затирают друг друга.

GChat не подключается к Telegram и не требует его аккаунта. Используются системные Unicode emoji; платные, пользовательские emoji и анимации Telegram в объём не входят. Обновление набора — отдельное изменение контракта, а не зависимость от внешнего API во время работы приложения.

## Технические границы следующего согласования

Предлагается расширять существующие DialogsModule, HTTPS REST, generated OpenAPI/SDK и device/runtime без второго транспорта и второго кеша. WSS продолжает передавать сигналы без текста. Backend хранит пересланное содержимое существующим серверным шифрованием, без новых криптографических библиотек или открытой копии текста в БД/логах.

Перед реализацией нужен согласованный технический контракт: маршруты и DTO пересылки/реакций; модель происхождения с серверной фильтрацией; атомарные проверки доступа и идемпотентности; шифрование новых полей и AAD; версии и долговечный курсор синхронизации реакций; миграция БД/локального кеша и поведение старых Web-клиентов. Существующая синхронизация редактирования не объявляется автоматически подходящей для реакций. iOS-код не меняется, ограничения совместимости deprecated-клиента фиксируются явно.

## Критерии приёмки

- На узком экране меню остаётся открытым после отпускания долгого нажатия и скрытия клавиатуры; тап запускает выбранное действие. Превью выбранного сообщения остаётся видимым в группе действий, исходник не дублируется и восстанавливается при закрытии. Группа ограничена visual viewport, включая короткий экран и увеличенный текст; прокрутка ленты и Tab сохраняют её. Завершённый тап снаружи и Escape закрывают меню; клавиатура и экранный диктор имеют эквивалентный доступ.
- Полный каталог заменяет команды без удвоения высоты группы; Назад/Escape возвращает команды, «Готово» закрывает меню. Выбор или снятие реакции в быстрой строке и полном каталоге закрывает всё меню после успеха с возвратом фокуса к источнику; при отказе панель остаётся открытой. Цвета берутся из действующей общей палитры.
- Копирование сохраняет точный текст. Для одной ссылки копируется адрес, для нескольких выбирается один; у стикеров и текста без ссылок лишних действий нет. Отказ Clipboard API виден и допускает ручное копирование.
- Пересылка создаёт одну копию выбранному человеку, в том числе при повторе после потерянного ответа. Отмена ничего не отправляет. Недоступный источник/получатель отклоняются сервером без утечки содержимого.
- Имя автора показывается при общей группе автора и получателя и отсутствует без неё также в DTO. Общая группа только пересылающего и получателя не раскрывает автора. Проверяются администратор, повторная пересылка, анонимное происхождение, изменение исходника и отзыв доступа перед commit.
- Несколько разных реакций от одного участника сохраняются независимо; повторное нажатие снимает только выбранную. Оба участника и все их устройства видят одинаковые счётчики и авторство после reconnect и офлайна, включая старые сообщения.
- Реакции не меняют порядок, непрочитанность и push. Пересланная копия не наследует реакции и последующие правки источника. Обычные черновики и outbox не теряются при обновлении клиента и локального хранилища.

## Открытые решения

Открытых продуктовых решений нет. HTTP/WS, модель данных, AAD, миграции, нормализация emoji и распознавание URL описаны в [техническом проекте](../backend/modules/dialogs/message-actions.md); реализация выполняется по принятому техническому контракту.
