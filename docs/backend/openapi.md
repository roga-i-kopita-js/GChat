# GChat: Swagger / OpenAPI

Статус контракта: draft. Реализация: подготовлена локально через @nestjs/swagger и плагин Nest CLI. Правила оформления контроллеров согласованы; доступность Swagger по окружениям ещё не согласована. Точная версия пакета указана в package.json. Спецификация строится из контроллеров и DTO при запуске HTTP-приложения; отдельного списка маршрутов или вручную поддерживаемого JSON нет.

## Адреса

При стандартном HOST и PORT:

- Swagger UI: `http://127.0.0.1:3000/docs`.
- OpenAPI JSON: `http://127.0.0.1:3000/docs-json`.

Swagger подключается в main.ts через setupSwagger до app.listen. UI и JSON доступны вместе с HTTP-приложением во всех окружениях. В текущей спецификации есть только реализованные `/health` и `/ready`. Swagger-маршруты не включаются в контракт как бизнес-endpoints.

## Автогенерация

Nest собирает пути, HTTP-методы, параметры и зарегистрированные модели из контроллеров. Плагин @nestjs/swagger в nest-cli.json дополняет метаданные при сборке:

- Файлы `*.dto.ts` и `*.entity.ts`: свойства классов, типы, обязательность, массивы, вложенные модели и поддерживаемые ограничения class-validator.
- Файлы `*.controller.ts`: типы успешных ответов из объявленных типов возвращаемых значений.
- Комментарии контроллеров и свойств: описания и summary благодаря introspectComments.
- esmCompatible сохраняет совместимость генерируемых импортов с ESM / NodeNext.

Плагин работает через Nest CLI в build, start и start:dev. После изменения контроллера или DTO приложение необходимо пересобрать или дождаться пересборки в watch-режиме.

## Правила для новых контроллеров

1. Описывать входные и выходные данные классами DTO, а не интерфейсами. DTO размещать в файлах с суффиксом `.dto.ts`.
2. Использовать декораторы class-validator для проверки входных DTO. Swagger описывает поддерживаемые ограничения, но не заменяет ValidationPipe.
3. Указывать тип возвращаемого значения: `ResponseDto` или `Promise<ResponseDto>`. Анонимный объект без объявленного DTO не гарантирует полноценную схему ответа.
4. Ошибочные ответы описывать явно декораторами вроде `@ApiServiceUnavailableResponse`. Условия throw внутри сервиса автоматически в документацию ошибок не превращаются.
5. Для уточнений использовать `@ApiProperty`, `@ApiOperation`, `@ApiResponse` и другие декораторы Swagger. Ручные уточнения дополняют автогенерацию.

Полный пример контроллера с авторизацией и DTO зафиксирован в [общих правилах backend](conventions.md#http-контроллеры-и-swagger). Минимальный пример метода:

```ts
/** Возвращает доступные контакты. */
@Get()
list(): Promise<ContactsResponseDto> {
  return this.contacts.list();
}
```

Для группировки контроллеры могут использовать `@ApiTags`. Healthcheck сгруппирован отдельно, DTO описывают ответы 200 и 503, включая checks.database и checks.redis. Его HTTP-поведение не изменено.

## Авторизация

В OpenAPI зарегистрирована схема Bearer, доступная через кнопку Authorize. Она не применяется глобально: публичные healthcheck-маршруты остаются публичными. При добавлении защищённых контроллеров нужно указать `@ApiBearerAuth()` и подключить реальный guard. Декоратор Swagger сам доступ не защищает. Сохранение авторизации между перезагрузками UI отключено.

## Проверки

HTTP-тесты `test/app.e2e.spec.ts` проверяют UI, JSON, автосборку маршрутов, документирование 503 и отсутствие глобального security на healthcheck. После сборки дополнительно проверять документ из скомпилированных контроллеров: успешные ответы, DTO, вложенные схемы, enum и комментарии. Jest / ts-jest сам плагин Nest CLI не запускает; проверка исходников не заменяет сборку.

Общие команды — в [README backend](../../applications/backend/README.md#сборка-и-проверки). Проверка скомпилированного документа обязательна при изменении DTO или CLI-плагина.

## Открытое решение

Определить, доступен ли Swagger во всех окружениях или управляется переменной окружения. Текущий подготовленный код включает его всегда; это не означает согласования данной политики.
