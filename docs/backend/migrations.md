# GChat: миграции PostgreSQL

Статус: черновик для обсуждения. В backend есть подключение PostgreSQL через Drizzle; Drizzle Kit, схема таблиц и команды миграций ещё не настроены. Ниже — предлагаемый контракт, не описание выполненной реализации.

## 1. Назначение

Миграции хранят версионируемые изменения схемы PostgreSQL в репозитории. Они позволяют привести локальную, тестовую и рабочую БД к схеме конкретной версии backend. Это часть инфраструктуры DatabaseModule; отдельный Nest-модуль не требуется.

## 2. Предлагаемый процесс

1. Разработчик изменяет TypeScript-описание таблиц.
2. Команда `db:generate` создаёт SQL-миграцию и метаданные Drizzle Kit.
3. Разработчик проверяет SQL, включая влияние на существующие данные.
4. SQL и метаданные коммитятся вместе с изменением кода.
5. Команда `db:migrate` применяет подготовленные миграции к выбранной БД.

Генерация выполняется при разработке. При развёртывании применяется подготовленный SQL из репозитория; заново генерировать миграции на рабочем сервере не предлагается. Прямое изменение схемы через `push` не входит в стандартный процесс.

Уже применённые миграции не редактируются. Исправление оформляется следующей миграцией. Изменения существующих данных при необходимости оформляются явным SQL и проверяются отдельно.

## 3. Размещение схем

Согласовано: TypeScript-описания таблиц хранятся рядом с бизнес-модулями, например `src/auth/auth.schema.ts` и `src/contacts/contacts.schema.ts`. Drizzle Kit собирает схемы по шаблону `src/**/*.schema.ts`. SQL-миграции и метаданные образуют единую историю для всего backend; отдельной истории на каждый модуль нет.

## 4. Предлагаемые команды

Из корня монорепозитория:

```sh
pnpm --filter @gchat/backend db:generate
pnpm --filter @gchat/backend db:migrate
```

Команды пока не реализованы. Они используют конфигурацию backend; для подключения применяется DATABASE_URL. Мигратор должен работать без Redis, запуска HTTP-сервера и загрузки бизнес-модулей, закрывать соединение и завершаться с ненулевым кодом при ошибке. URL и секреты не выводятся.

## 5. Применение и сбои

Согласовано: миграции запускаются отдельной командой `db:migrate` перед запуском новой версии backend. HTTP-приложение не запускает миграции автоматически и не изменяет схему при старте.

Согласовано: используется стандартный механизм миграций Drizzle, без собственной блокировки PostgreSQL или Redis и без дополнительного протокола ожидания. В одном окружении миграции запускаются последовательно процессом развёртывания.

В установленной версии drizzle-orm PostgreSQL-мигратор хранит журнал в `drizzle.__drizzle_migrations`, читает последнюю применённую миграцию и выполняет следующие миграции в транзакции. Отдельной advisory-блокировки и гарантии сериализации двух параллельных миграторов этот механизм не предоставляет. Повторный последовательный запуск и конкурентный запуск — разные сценарии; безопасность конкурентного запуска не заявляется. Реализацию стандартного механизма выбранной версии Drizzle Kit следует также проверить при подключении инструмента.

При ошибке запуск новой версии останавливается. Нельзя считать произвольный SQL автоматически откатываемым: транзакционность и допустимость конкретных DDL-операций проверяются при подготовке миграции. Повторное применение и журнал выполненных миграций проверяются на тестовой БД.

Автоматические down-миграции не предлагаются. Исправления выполняются следующей миграцией; восстановление из резервной копии — отдельная эксплуатационная процедура. Откат версии приложения допустим только при совместимой схеме.

## 6. Границы первого шага

Первый шаг — инструменты, конфигурация, команды и проверка мигратора. Таблица users и другие бизнес-таблицы добавляются вместе с соответствующими модулями. Фиктивные таблицы в основную схему не добавляются.

## 7. Проверки

- Пустая тестовая БД получает ожидаемую схему.
- Повторный запуск не применяет выполненные миграции заново.
- Новая миграция корректно применяется поверх предыдущего состояния.
- Ошибка SQL приводит к ненулевому коду завершения и освобождению соединения.
- Для запуска мигратора не требуются Redis и HTTP-сервер.
- Секреты подключения не попадают в вывод ошибок.
