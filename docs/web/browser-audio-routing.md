# Воспроизведение входящего аудио через Web Audio

Дата: 2026-11-16, Asia/Nicosia. Пользователь явно согласовал внедрение варианта 2 для PWA. Требуемое поведение и критерии приёмки находятся в [аудиоконтракте device](device-api.md#входящий-голос-в-браузерном-профиле-без-audiocontextsetsinkid); этот документ сохраняет основание выбора схемы.
## Основание

На iPhone 14 / iOS 26.6.2 пользователь подтвердил нестабильное физическое переключение аудиовыхода в разговоре: выбранная строка меняется, звук остаётся на прежнем выходе. Подробности и предыдущие проверки — [WEB-UI-005](ui-bugs.md#web-ui-005--недоступная-смена-аудиовыхода-в-pwa).

В отдельном диагностическом тесте пользователь сообщил: режим 1 с обычным входящим WebRTC-треком не работает; режим 2 с воспроизведением через Web Audio и режим 3 с двумя треками работают. Это подтверждает работающий путь обхода в проверенной среде, но ещё не означает приёмку интеграции в основной клиент. Симптом соответствует [WebKit 320087](https://bugs.webkit.org/show_bug.cgi?id=320087); наличие исправления в main WebKit не доказывает его поставку в используемой версии iOS.

## Решение и мотивировка

В профиле с HTMLMediaElement.setSinkId без AudioContext.setSinkId входящий голос воспроизводится через существующий граф Web Audio / ContextOutput. Выбор по возможностям API позволяет применить работающий путь режима 2 без проверки User-Agent и без второго передаваемого трека из режима 3. Публичный device API, нативный движок и медиапротокол не меняются.

Диагностический тест подтвердил возможность обхода на одном iPhone. Интеграция и физическая приёмка основного клиента проверяются отдельно по критериям контракта. Открытых решений для реализации согласованного объёма нет.
