# Общая карточка пользователя Web

Принятый пользователем контракт общего доменного компонента для отображения собеседников в списках диалогов и звонков. Дополняет [контракт Web](README.md#общая-оболочка-и-ui-kit); содержимое списка диалогов определяет [контракт диалогов](dialogs.md#список).

## Причина и границы

До объединения список звонков уменьшал аватар до 36 px, а список диалогов использовал 44 px. В звонках цвет зависел от имени, в диалогах — от ID собеседника. Общий примитив `Avatar` уже существовал, но геометрию и подпись независимо задавали страницы.

`UserCard` в `applications/web/src/features/users/` общий для `features/calls` и `features/dialogs`. Он отображает идентичность пользователя и использует `Avatar` из UI kit. Размещение следует существующей границе: доменные компоненты принадлежат features/app, недоменные примитивы — shared/ui.

Объём — строки собеседников в списках на `/calls` и `/dialogs`. Крупная карточка выбранного контакта, активный звонок, входящий вызов, подтверждение звонка, шапка переписки и администрирование сохраняют свои функциональные компоненты и размеры; общие цвета аватара и стабильность по ID распространяются на них по [контракту оформления](../design/winter-theme-task.md).

## Контракт

- Входные данные: `userId: string`, `displayName: string`, необязательные `subtitle: ReactNode` и `multiline: boolean` (по умолчанию true). Подпись принимает текст или готовый неинтерактивный фрагмент, включая иконку направления вызова. Компонент получает готовые данные, не загружает профиль и не обращается к device, роутеру или runtime.
- Карточка отображает круглый аватар с инициалами, имя и необязательную подпись. Цвет определяется по `userId` существующим алгоритмом и общей градиентной палитрой `Avatar` по [контракту оформления](../design/winter-theme-task.md), поэтому одинаковый пользователь имеет одинаковый цвет в обоих списках.
- Размер аватара в обоих списках — 44 × 44 CSS px через `--ui-control-height`; размер инициалов — `--ui-avatar-font-size` (13 px), вес — `--ui-avatar-font-weight` (500). Расстояние между аватаром и текстом — `--ui-space-3`, имя — `--ui-font-body` с весом `--ui-weight-semibold`, подпись — `--ui-font-caption`. Геометрией и типографикой этой группы владеет компонент и его соседний CSS; страницы не переопределяют аватар вложенными селекторами.
- Аватар не сжимается. Текстовая область может сжиматься; по умолчанию длинное имя и подпись занимают по одной строке и сокращаются многоточием, полный текст остаётся в DOM. В режиме `multiline` имя и подпись переносятся, включая длинные непрерывные слова; геометрией переноса владеет UserCard. История использует этот режим по [согласованному оформлению](../design/calls-history.md#визуальное-соответствие-gchat); остальные списки также поддерживают перенос длинного имени по принятому оформлению. Декоративный аватар скрыт от accessibility tree, имя доступно через текст.
- Компонент не создаёт ссылку или кнопку. История звонков и список диалогов помещают его внутрь ссылки на сведения или переписку, контакты — внутрь кнопки выбора. Отдельные кнопки «Написать» и «Позвонить» остаются соседями, без вложенных интерактивных элементов.
- Подпись задаёт список: в контактах «Голосовой звонок», в истории — направление, результат и длительность по контракту истории, в диалогах — превью при наличии доступного последнего сообщения по [контракту диалогов](dialogs.md#список). Неинтерактивный фрагмент истории владеет иконкой и типографикой результата (12 px через общий токен), карточка — размещением группы. Время и индикатор непрочитанного остаются рядом с карточкой и принадлежат странице.
- Выбор контакта, текущий диалог, disabled-состояния, маршруты, обработчики действий, внешние отступы и высота строк принадлежат существующим страницам. Области нажатия сохраняют размер не менее 44 px. Скелетоны аватаров в обоих списках также используют размер 44 px.

## Критерии приёмки и проверки

1. Оба списка используют один `UserCard`; размер, инициалы и цвет одного пользователя совпадают, в том числе при изменении отображаемого имени.
2. Длинное имя и доступные действия помещаются на ширине 360, 390 и 430 CSS px без горизонтальной прокрутки; аватар сохраняет 44 × 44 px. На настольном экране действует та же геометрия.
3. Ссылка диалога, выбор контакта, звонок и переход к переписке сохраняют существующее поведение, доступные имена, клавиатурную навигацию и ограничения доступности действий. Время и непрочитанное отображаются как прежде.
4. Нет локальных переопределений размера аватара карточки в CSS страниц; геометрия скелетонов соответствует карточке.
5. В обоих списках есть вторая строка: в истории — направление, результат и длительность, в контактах — «Голосовой звонок», в диалогах — превью при наличии доступного последнего сообщения по контракту диалогов. Дополнительных запросов сообщений нет; индикатор непрочитанного сохраняет прежнее поведение. Режим истории поддерживает длинные имена и увеличение текста до 200% без наложения на время и действие звонка.
6. После реализации выполняются typecheck, build и относящиеся проверки согласно [инструкциям Web](../../applications/web/AGENTS.md), а также `pnpm docs:check`. Визуальная проверка обоих списков выполняется отдельно от проверки типов и сборки.

## Открытые решения

В принятом объёме открытых проектных решений нет. Границы, размещение компонента и единый размер аватара согласованы пользователем.
