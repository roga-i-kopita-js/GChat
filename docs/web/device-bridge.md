# Bridge устройства

Целевой публичный интерфейс определяет принятая [спецификация device](device-api.md): методы сервисов, enum-события и новые возможности камеры/HTTP/навигации. Ниже сохраняются текущий командный протокол и алгоритмы разрешений/файлов как внутренний механизм адаптеров. Execute и wait/cancel не остаются публичными для фич после миграции. Реализация нового фасада пока отсутствует.

Принятый контракт единого командного bridge по [D011](../architecture/decisions/D011-native-device-settings.md). Интерфейс настроек описан в [Settings](settings.md). Реализация добавлена в Web и iOS. Системные диалоги, реальное аудио и файловые провайдеры на физическом iPhone требуют отдельной интеграционной приёмки. Методы устройства не заменяют Auth или WSS. Правила разрешений и файлового доступа не зависят от аккаунта GChat.

## Один интерфейс команд

Публичная форма — `bridge.execute({ command, args })`. TypeScript связывает каждое имя команды с конкретными аргументами и результатом. Возвращается Promise результата; отказ — типизированная ошибка. Диспетчер принимает только перечисленные команды и проверяет аргументы до обращения к устройству. Неизвестные поля отклоняются. Публичных методов getSnapshot/subscribe и отдельных платформенных фасадов нет.

Примеры формы API, не код реализации:

```ts
await bridge.execute({ command: 'device.state.read', args: {} });
await bridge.execute({
  command: 'permission.request',
  args: { resource: 'camera' },
});
await bridge.execute({
  command: 'file.pick',
  args: { multiple: true, accept: [] },
});
```

Bridge создаётся один раз на время жизни основного документа и выбирает адаптер по существующему правилу embedded до выполнения React. Native-отказ никогда не включает браузерный адаптер. В браузере выполнение локально и не требует Capacitor-плагина. UI владеет разметкой, переводами, отображением ошибок и подтверждением слышимости.

Чтение состояния, ожидание изменений и просмотр сохранённых ссылок не вызывают системный диалог, захват, получение координат или запись файлов. Запросы разрешений, выбора файлов, выхода и звука доходят до системного API непосредственно из пользовательского обработчика, без предварительного await, теряющего browser user activation.

### Общие типы результата

- `Permission`: unknown, prompt, denied, restricted, granted или limited. unknown означает невозможность достоверно прочитать состояние; restricted — системное ограничение, которое пользователь не обязательно может изменить. limited означает частичный доступ.
- `ResourcePermission`: `{ permission, settingsHint }`, где settingsHint — appSettings, siteSettings или none. Это инструкция о настройках, а не модель доступности действий.
- `FileRef`: `{ id, name, kind, persistence }`. id — непрозрачный UUID, kind — file или directory, persistence — persistent или session. Абсолютные пути, URL провайдера и bookmark не выдаются.
- `FileMetadata`: `{ ref, size, modifiedAt, mimeType, version }`. Для папки size и mimeType равны null, неизвестная дата равна null. Даты — ISO 8601 UTC; version — непрозрачный токен наблюдаемой версии либо null, если провайдер его не даёт.
- `OperationResult`: `{ outcome }`, где outcome — completed или cancelled. Отмена пользователем системного диалога — cancelled, а не ошибка. Результат команды чтения или выбора содержит данные дополнительно к outcome.

Ограничения числовых аргументов: целые безопасные числа JavaScript, без отрицательных значений, кроме явно разрешённых ниже случаев. UUID проверяются по формату. Имена файлов — отдельные непустые компоненты без `/`, `\`, NUL, `.` и `..`; пределы длины и запрещённые платформой имена проверяет адаптер. Сырые пути и произвольные URL не принимаются.

### Состояние устройства

`device.state.read` с `{}` возвращает `{ revision, microphone, camera, geolocation, audio, push, files }`:

| Блок               | Поля                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| microphone, camera | ResourcePermission                                                                                                       |
| geolocation        | ResourcePermission и `{ accuracy: 'full' или 'reduced' или 'unknown', service: 'enabled' или 'disabled' или 'unknown' }` |
| audio              | `{ routeName: string или null, test: AudioTest или null }`                                                               |
| push               | `{ permission, alert, sound, badge, delivery }`                                                                          |
| files              | `{ retainedCount: number }`                                                                                              |

Push permission использует Permission. alert/sound/badge — enabled, disabled или unknown. delivery — unavailable, disabled, enabling, enabled или error. iOS authorized нормализуется в granted, provisional/ephemeral — limited. В первом этапе iOS delivery всегда unavailable. Готовность PushKit/CallKit и подключение WSS из разрешения обычных уведомлений не выводятся. В браузере enabled требует действующей подписки и серверной регистрации текущей сессии; разрешение ОС не привязывается к аккаунту, серверная подписка продолжает подчиняться [Push](../backend/modules/push.md).

AudioTest содержит `{ id, kind, status, errorCode }`, где kind — microphone или sound, status — running, completed, cancelled или failed; errorCode равен null, кроме failed. Слышимость не входит в системный результат: её подтверждение хранится в UI до закрытия настроек. Последний терминальный тест хранится до нового теста или инвалидирующего события.

revision — монотонное безопасное целое в течение жизни документа. Если значение достигло предела безопасного целого, bridge завершает текущий цикл ошибкой INTEGRATION_ERROR; после нового цикла счёт начинается заново. Чтение состояния не увеличивает revision при отсутствии изменений.

## Команды разрешений, аудио и push

| Команда              | Аргументы                                                 | Результат                                                                                                  |
| -------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| device.state.read    | `{}`                                                      | Актуальное состояние устройства                                                                            |
| permission.read      | `{resource: 'microphone' или 'camera' или 'geolocation'}` | ResourcePermission; для geolocation также accuracy и service                                               |
| permission.request   | `{resource}` из того же списка                            | `{outcome, state: ResourcePermission}`; для geolocation также accuracy и service                           |
| device.settings.open | `{}`                                                      | `{outcome}` после передачи управления настройкам приложения; если открытия нет, UNSUPPORTED с settingsHint |
| audio.test.start     | `{kind: 'microphone' или 'sound'}`                        | `{testId}` после принятия теста; завершение и ошибка выполнения видны через состояние/изменения            |
| audio.test.stop      | `{testId}`                                                | `{outcome}` после освобождения ресурсов; повторная остановка терминального теста безопасна                 |
| audio.output.select  | `{}`                                                      | `{outcome, routeName: string или null}`                                                                    |
| call.prepareOutgoing | `{}`                                                      | `{outcome, microphone: ResourcePermission}`; completed только при granted                                  |
| push.enable          | `{}`                                                      | `{outcome, push}` после действующей браузерной регистрации                                                 |
| push.disable         | `{}`                                                      | `{outcome, push}` после удаления регистрации и подписки по действующему контракту                          |

Для permission.request отказ пользователя возвращает completed с denied/restricted, а не ложный granted. В браузере неизвестный статус разрешения не превращается в запрет; запрос выполняет соответствующий системный API. granted по прежнему снимку не гарантирует открытие устройства; актуальная ошибка операции возвращается отдельно.

`call.prepareOutgoing` читает актуальное состояние и при prompt/unknown запрашивает микрофон по явному нажатию. denied/restricted возвращает PERMISSION_DENIED с settingsHint без серверного вызова. Команда не создаёт звонок и не заменяет звонковый движок. Продолжение исходящего выполняется только после completed и проверки актуальности попытки. Существующие call.create/placeCall не обходят этот шаг в общем UI. Неопределённый результат call.create не повторяется автоматически. В native с nativeCalls: false UI сохраняет запрет звонков.

### Аудио

Микрофонный тест требует granted; отдельно разрешение не запрашивает. В браузере AudioPreparation переиспользуется через адаптер. Запрос разрешения микрофона может кратко открыть и закрыть stream, но тест после выдачи разрешения не запускается автоматически. iOS использует системное разрешение и временный захват без файловой записи.

Одновременно выполняется один аудиотест. При звонке, его запуске или занятой аудиосессии возвращается BUSY. Нативный модуль проверяет это самостоятельно, независимо от UI. Появление входящего вызова, interruption, смена маршрута, уход в фон, закрытие окна, logout, новый цикл и уничтожение WebView останавливают тест и освобождают принадлежащие ему ресурсы. Поздняя остановка прежнего testId не затрагивает следующий тест. Переход состояния теста увеличивает revision. Тест не деактивирует аудиосессию, уже переданную звонковому движку.

iOS первого этапа отклоняет audio.output.select как UNSUPPORTED; показывает текущее доступное название системного выхода, не обещая маршрут будущего разговора. Браузерный адаптер сохраняет selectAudioOutput/setSinkId там, где они поддерживаются, иначе возвращает UNSUPPORTED. Громкость задаётся средствами ОС.

### Камера и геопозиция

iOS запрашивает камеру через системное разрешение без запуска capture session. Геопозиция запрашивается только When In Use; Always и фоновое отслеживание не включаются. restricted, выключенные location services и reduced accuracy не маскируются под полный доступ. Для новых запросов нужны строки назначения NSMicrophoneUsageDescription, NSCameraUsageDescription и NSLocationWhenInUseUsageDescription в Info.plist.

Браузер использует Permissions API для чтения там, где доступно; неподдерживаемый descriptor даёт unknown, а отсутствие самого целевого API — UNSUPPORTED при выполнении команды. Каждое чтение разрешения выполняет новый query: сохранённый PermissionStatus используется только для подписки на change, поскольку [Safari может не обновить его после изменения настроек](https://bugs.webkit.org/show_bug.cgi?id=257710). Это относится и к чтению после permission.request, и к возвращению из настроек браузера; чтение не открывает микрофон или камеру. Запрос камеры использует только video, затем останавливает все tracks. Запрос геопозиции выполняется разово без высокой точности, с maximumAge: 0 и timeout: 10000; результат отбрасывается. Если позицию получить не удалось после выдачи разрешения, адаптер перечитывает permission: достоверное granted возвращается с ним, отсутствие достоверного статуса возвращает TIMEOUT/DEVICE_UNAVAILABLE без координат. Длительное ожидание диалога не подменяется автоматическим denied.

### Push

Браузерный адаптер переиспользует действующую Web Push реализацию, VAPID, серверную регистрацию и ограничения сессии. Не создаётся второй call client, WSS или подписка. Push permission запрашивается только внутри push.enable по нажатию пользователя, не перед звонком и не при открытии настроек.

iOS читает настройки обычных уведомлений и открывает настройки приложения. Для принятых [уведомлений диалогов](bootstrap.md#системные-уведомления) push.enable по нажатию запрашивает системное разрешение, запускает обычную APNs-регистрацию и возвращает актуальное состояние доставки; push.disable удаляет обычную регистрацию и отключает её для приложения. Без подтверждения backend состояние enabled не показывается; ожидание регистрации — enabling, отказ — error/unavailable. APNs/VoIP token не выдаются через bridge. Эти команды не меняют VoIP/CallKit и не обещают фактическую доставку провайдером.

## Файловые команды

Все команды работают с непрозрачными fileId/directoryId из FileRef. Bridge сохраняет платформенную ссылку внутри адаптера. Идентификатор не позволяет выйти за выбранную область, обращаться к произвольному пути или разыменовывать символическую ссылку наружу выбранной папки. Доступный provider может отклонить операцию; полный набор команд не обещает поддержку каждым браузером и провайдером.

| Команда             | Аргументы                                                                  | Результат                                                                                            |
| ------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| file.pick           | `{multiple: boolean, accept: string[]}`                                    | `{outcome, entries: FileMetadata[]}`; accept — MIME types, пустой список означает все типы           |
| directory.pick      | `{}`                                                                       | `{outcome, entry: FileMetadata или null}`                                                            |
| file.access.list    | `{cursor: string или null, limit: number}`                                 | `{entries: FileRef[], nextCursor: string или null}` сохранённых корневых доступов                    |
| file.access.restore | `{id}`                                                                     | FileMetadata; при утрате доступа ACCESS_LOST без автоматического диалога                             |
| file.access.forget  | `{id}`                                                                     | `{outcome}`; удаляет сохранённую ссылку и зависимые ссылки bridge, не файл и не системное разрешение |
| file.stat           | `{id}`                                                                     | FileMetadata                                                                                         |
| directory.list      | `{directoryId, cursor: string или null, limit: number}`                    | `{entries: FileMetadata[], nextCursor: string или null}`                                             |
| file.read           | `{fileId, offset: number, length: number}`                                 | `{dataBase64, bytesRead: number, eof: boolean, version: string или null}`                            |
| file.create         | `{directoryId, name}`                                                      | FileMetadata нового пустого файла; существующий файл не перезаписывается                             |
| directory.create    | `{directoryId, name}`                                                      | FileMetadata новой папки                                                                             |
| file.write.begin    | `{fileId, mode: 'replace' или 'update', expectedVersion: string или null}` | `{writeId}`                                                                                          |
| file.write.chunk    | `{writeId, offset: number, dataBase64}`                                    | `{bytesWritten: number}` во временную копию                                                          |
| file.write.commit   | `{writeId}`                                                                | FileMetadata после завершения записи                                                                 |
| file.write.abort    | `{writeId}`                                                                | `{outcome}` после удаления временной копии; повтор безопасен                                         |
| file.saveAs         | `{sourceFileId, suggestedName}`                                            | `{outcome, entry: FileMetadata или null}` после системного выбора назначения                         |
| file.export         | `{sourceFileId, suggestedName}`                                            | `{outcome}` после подтверждённой передачи файла системному экспорту/загрузке                         |
| file.copy           | `{id, destinationDirectoryId, name}`                                       | FileMetadata новой копии                                                                             |
| file.move           | `{id, destinationDirectoryId, name}`                                       | FileMetadata перемещённого объекта                                                                   |
| file.rename         | `{id, name}`                                                               | FileMetadata объекта                                                                                 |
| file.remove         | `{id, recursive: boolean}`                                                 | `{outcome}`                                                                                          |

limit — от 1 до 200, offset — от 0, length — от 1 до 262144 байт. dataBase64 использует стандартный base64; декодированный chunk не более 262144 байт. Чтение за концом возвращает пустые данные и eof: true. Пустой файл допустим. Размер полного файла не ограничивается размером JSON сообщения: данные передаются частями без загрузки всего файла в память Web/native. Нехватка места или квота возвращает STORAGE_FULL.

Курсоры непрозрачны, действуют только для конкретного каталога/реестра и текущего цикла. Порядок обхода фиксируется для страницы адаптером; изменение каталога может дать CONFLICT и требует нового обхода с cursor: null. Листинг не рекурсивен. Метаданные и чтение проверяются заново на каждой операции. Другой тип объекта возвращает WRONG_TYPE.

### Запись и изменение файлов

writeId — UUID текущего цикла. Для replace временная копия изначально пуста; для update содержит текущий файл. chunk записывает байты по offset; пропуск за концом временной копии запрещён как INVALID_ARGUMENT. Перекрывающая запись разрешена; повтор того же chunk по тому же offset безопасен внутри незавершённой записи. Размер исходного файла меняется только при commit. В replace итоговая длина равна длине записанной временной копии; update не обрезает остаток файла. Для сокращения файла используется replace.

Если expectedVersion не null, несовпадение до begin или commit возвращает CONFLICT. Если провайдер не может проверить версию, begin с ненулевым expectedVersion возвращает UNSUPPORTED; автоматическая подмена на безусловную запись не допускается. При expectedVersion: null условная защита не запрашивается. Проверка версии и замена не обещают межпроцессную транзакцию у произвольного провайдера.

Адаптер использует временный файл/платформенный writable stream и coordinated commit. Если провайдер не позволяет отложить изменение до commit, запись в него возвращает UNSUPPORTED до изменения исходника. После подтверждённого commit исходная ссылка остаётся действительной, метаданные обновляются. При неопределённом исходе commit возвращается OUTCOME_UNKNOWN и требуется file.stat/повторный выбор; команда не повторяется автоматически.

При закрытии документа, новом цикле или logout незавершённые записи отменяются, временные данные удаляются; уже завершённое изменение остаётся. Прерванное системное изменение не объявляется откатанным без подтверждения. При следующем запуске адаптер очищает незавершённые локальные временные записи. Предоставленный доступ при этом сохраняется независимо от аккаунта.

create/copy/move/rename возвращают ALREADY_EXISTS при конфликте назначения, без неявной перезаписи. Копирование папки рекурсивно. Перемещение в собственное поддерево запрещено. Адаптер обновляет известные ссылки после успешного переименования/перемещения и инвалидирует их после удаления; перемещение между провайдерами с неопределённой семантикой возвращает UNSUPPORTED до изменения.

Пустая папка удаляется с recursive: false; непустая требует recursive: true. Запись, удаление и перемещение выполняются только по явной команде, без фоновой очистки пользовательских объектов. Платформа может не иметь корзины; file.remove не обещает восстановление. Текст подтверждения удаления и выбор объектов относятся к вызывающему пользовательскому сценарию.

Операции с несколькими объектами не обещают общую транзакцию. При частичном выполнении возвращается PARTIAL_FAILURE с завершёнными fileId и ссылкой на созданное назначение, если оно существует. Нет автоматического удаления успешно скопированных объектов. Неопределённый результат модификации не повторяется автоматически.

### Сохранение доступа и различия платформ

iOS использует UIDocumentPicker и security-scoped URLs; для продолжения доступа сохраняются bookmarks. Каждое обращение балансирует start/stopAccessingSecurityScopedResource и использует NSFileCoordinator. Устаревший bookmark обновляется при успешном разрешении; утраченный доступ даёт ACCESS_LOST и требует повторного выбора. Сырые bookmarks остаются native. Публичный id не меняется при успешном восстановлении.

В браузере адаптер использует File System Access API при наличии соответствующих методов; handles сохраняет в IndexedDB текущего origin. Реестр доступов общий для аккаунтов этого origin. При необходимости повторного разрешения запрос выполняется только по пользовательскому действию. Отсутствие API не маскируется под granted.

Для выбора и чтения файлов без File System Access API используется file input: результат имеет persistence: session. Экспорт может использовать обычную браузерную загрузку. Её результат completed подтверждает передачу файла механизму загрузки, не успешную запись на диск: наблюдаемого подтверждения браузер не предоставляет. file.export не возвращает файловый доступ. file.saveAs требует подтверждённого системного назначения и возвращает UNSUPPORTED, если среда позволяет только загрузку без handle.

Операции с папками, изменение выбранного файла, перемещение и удаление без необходимого API возвращают UNSUPPORTED. Наличие браузерного picker API не гарантирует поддержку всех операций. Мобильный Safari и остальные целевые браузеры проверяются отдельно, а не считаются эквивалентными desktop Chromium. Не создаётся виртуальный файловый менеджер вместо недоступного системного API.

## Изменения состояния через команды

Для событий используется та же точка входа: `device.changes.wait` с `{afterRevision, timeoutMs}`. afterRevision — полученная revision текущего документа, timeoutMs — от 1000 до 30000. Результат `{revision, changed, timedOut}`, где changed — список из microphone, camera, geolocation, audio, push, files. Если изменения уже есть, результат немедленный; иначе Promise ждёт системное событие или срок. Это ожидание события, не периодическое чтение системных API.

В одном документе допускается одно ожидание. Второе возвращает BUSY. afterRevision из будущего даёт INVALID_ARGUMENT. Bridge хранит накопленные изменения до подтверждения новой revision очередным ожиданием; при потере детальной истории возвращает все блоки. Событие между чтением состояния и началом ожидания не теряется. При timedOut: true revision не меняется; UI может продолжить ожидание. Начальный или запоздалый ответ не затирает более новую revision.

Вызывающий UI после уведомления выполняет device.state.read. Закрытие настроек отправляет `device.changes.cancel` с `{}`; команда идемпотентна, ожидающий Promise завершается CANCELLED. Наблюдение, начатое позднее, не отменяется старой native-командой: отмена связывается с внутренним requestId активного ожидания на момент вызова.

Адаптер слушает доступные системные события разрешений, маршрута и foreground; не создаёт постоянный опрос по таймеру. Если платформа не сообщает изменение, актуализация гарантируется при следующем открытии/foreground/команде, а не выдуманным событием. При новом цикле ожидания отменяются и revision начинается заново. В foreground UI перечитывает состояние и возобновляет ожидание. Перед исходящим выполняется call.prepareOutgoing, а не доверие прежнему тесту.

## Внутренний транспорт iOS

В Swift-плагине GChat добавляется один диспетчер `executeDeviceCommand`. Существующие методы Auth/WSS не меняются. Web-адаптер добавляет к `{command, args}` внутренний envelope `{deviceBridgeVersion: 1, cycleId, requestId}`. cycleId и requestId — UUID; повторный активный requestId отклоняется. Результат содержит те же version/cycleId/requestId и result либо error. Неверный envelope возвращает INVALID_ARGUMENT; версия — UNSUPPORTED_VERSION.

Только доверенный основной документ выбранного сервера с активной сессией и текущим циклом получает доступ к командам. Bootstrap формы сервера, вложенные документы и внешние origin их не получают. Это условие вызова не связывает сохранённые разрешения с аккаунтом. Следующий выбранный доверенный сервер использует тот же реестр разрешений установленного приложения по согласованному правилу.

Публичные device.changes.wait/cancel отображаются на ожидающий native-запрос и отмену его requestId через тот же диспетчер. Внутренняя cancel-команда использует requestId отменяемого ожидания: это единственное исключение из запрета повторного активного requestId. Если ожидание ещё не зарегистрировалось, native запоминает отмену для этого ID; новое ожидание с другим ID не затрагивается; отдельного канала событий настроек нет. В браузере ожидание реализуется локальной очередью. Ни cycleId, ни requestId не выбираются вызывающим компонентом.

MainActor владеет системными диалогами и жизненным циклом. Дисковые операции и кодирование больших данных не блокируют UI-поток. Один системный диалог в момент времени; конфликт возвращает BUSY. Передача команд не даёт права исполнять произвольный selector, JS, shell, путь или URL.

Перезагрузка WebView, logout и смена цикла отменяют ожидания, тесты, диалоги, где это поддерживается, и незавершённые операции. Неотменяемый системный prompt может завершиться поздно; его результат не применяется к новому UI. Предоставленное ОС разрешение остаётся действительным и читается заново. Поздно выданный stream освобождается. Уже выполненное файловое изменение не выдаётся за отменённое.

## Ошибки, сроки и повтор

Публичная ошибка содержит `{code, command, settingsHint?, outcome?, completedIds?, destinationId?}`. outcome при неопределённом/частичном изменении — unknown или partial. Системный текст, абсолютные пути, содержимое файлов и секреты не передаются в сообщения ошибки. UI сопоставляет код с понятным текстом.

| Код                                    | Значение                                                          |
| -------------------------------------- | ----------------------------------------------------------------- |
| INVALID_ARGUMENT                       | Неизвестная команда/поле, некорректный аргумент или идентификатор |
| UNSUPPORTED                            | Операция отсутствует в среде или у провайдера                     |
| UNSUPPORTED_VERSION, INTEGRATION_ERROR | Несогласованный Web/iOS или повреждённый ответ                    |
| PERMISSION_DENIED, RESTRICTED          | Отказ или системное ограничение                                   |
| ACCESS_LOST, NOT_FOUND, WRONG_TYPE     | Утрачен доступ, объект отсутствует или имеет другой тип           |
| BUSY                                   | Занятый системный диалог, аудио или файловый объект               |
| CANCELLED                              | Отмена жизненным циклом или явной командой                        |
| TIMEOUT, DEVICE_UNAVAILABLE            | Истёк срок технической операции или устройство недоступно         |
| ALREADY_EXISTS, CONFLICT               | Конфликт назначения или наблюдаемой версии                        |
| STORAGE_FULL, IO_ERROR                 | Квота/место или ошибка чтения/записи                              |
| PARTIAL_FAILURE, OUTCOME_UNKNOWN       | Частично выполненное изменение или неопределённый результат       |
| UNAUTHENTICATED, BRIDGE_UNAVAILABLE    | Нет актуальной native-сессии или связи с плагином                 |
| PUSH_UNAVAILABLE, NETWORK_ERROR        | Push не настроен или зависимая сетевая операция не выполнена      |

Локальное чтение состояния, открытие настроек и отдельная файловая операция без диалога имеют технический deadline 30 секунд; UI не блокируется синхронным ожиданием. Ожидание решения пользователя в диалоге не ограничивается этим deadline; прекращается по отмене/жизненному циклу. Для browser geolocation отдельно действует указанный timeout 10 секунд. Время получения данных provider, состояние busy и ошибки отображаются в UI.

Если операция изменения уже передана провайдеру и срок истёк, результат OUTCOME_UNKNOWN, а не безопасный TIMEOUT. Необратимое действие не повторяется автоматически. Чтение можно повторить; при ACCESS_LOST предлагается повторный выбор; при PERMISSION_DENIED — настройки/инструкция. Произвольный системный prompt не открывается автоматически при повторном чтении.

## Доставка и критерии приёмки

Согласованная пара Web/iOS устанавливается для разработки; открытый документ ради настроек принудительно не перезагружается. Новая нативная операция требует новой сборки приложения. Будущая политика совместимости публичных релизов определяется перед первым релизом.

1. Все согласованные возможности вызываются через bridge.execute; компоненты не определяют среду и не обращаются к системным API. Командная типизация и runtime-валидация согласованы для обоих адаптеров.
2. В браузере сохраняются существующие аудио и Web Push сценарии; в iOS не вызываются браузерные mediaDevices, AudioContext, PushManager или Notification.requestPermission. Нет второго WSS, call engine или подписки.
3. Физический iPhone подтверждает первый запрос, отказ и изменение разрешений микрофона/камеры/When In Use location через настройки. Нет автоматического захвата/запроса при открытии окна, координат или camera stream в UI.
4. Аудиотесты проверены с системным выходом и гарнитурой. Ресурсы освобождаются по завершении и всем согласованным отменам; тест не вмешивается в звонковую аудиосессию. Запоздалые ответы/остановки не влияют на новую попытку.
5. До серверного исходящего получен актуальный результат call.prepareOutgoing. При отказе нет call.create; отменённая попытка после позднего согласия не восстанавливается. Запрет push не блокирует исходящий.
6. Проверены все файловые команды, пустые и многочастные файлы, имена, границы выбранной области, утрата доступа, конфликт назначения/версии, отмена записи и частичный исход. Экспорт загрузкой не выдаётся за подтверждённую запись.
7. На iOS подтверждено восстановление bookmark после перезапуска и повторный выбор при утрате доступа. В браузере persistent и session различаются; отсутствие API даёт UNSUPPORTED. Смена аккаунта/сервера не очищает общий предоставленный доступ.
8. Ожидание изменений не теряет событие между чтением и ожиданием, корректно отменяется и не опрашивает разрешения по таймеру. Смена маршрута сбрасывает подтверждение старого звукового теста.
9. Неизвестные команды, лишние поля, неверная версия, origin/frame/cycle и запросы bootstrap отклоняются до операции. В ошибках и логах нет файлового содержимого, координат, путей, bookmarks, токенов или media data.
10. Unit-тесты адаптеров и диспетчера проверяют командную матрицу и отмены на fixtures. Web typecheck/build/относящиеся тесты, NativeCore tests и iOS build дополняются физической приёмкой. Fixture не подтверждает реальный звук, системные диалоги, provider или доставку push.
