# Восстановление обновления старого Web-клиента

Предложение требует согласования пользователем до реализации. Действующий порядок обновления и защита звонков описаны в [контракте Web](README.md#кеш-фронта-и-обновления); обычное подтверждение — в [контракте диалога](update-dialog.md).

## Проблема и действующее восстановление

Сборка коммита `02d7daf` для серверного размещения создаёт `index-BpFf69QB.js`. При запросе обновления свободный владелец WSS зацикливается в `yieldForUpdate → stopConnection → disposeMedia → set → yieldForUpdate`. Исключение возникает до освобождения shared lock `gchat-frontend-update`, поэтому запрос активации новой сборки остаётся в очереди. Исправление в `008d3b1` предотвращает рекурсию в новом JS, но не меняет уже выполняемый код старых окон.

Старый service worker использует cache-first для оболочки. Пока остаётся другое контролируемое окно, обычная перезагрузка может снова загрузить старый HTML и JS, а новая сборка остаётся в состоянии waiting.

Доступное сейчас восстановление: завершить звонки, закрыть все вкладки и окна GChat в этом браузерном профиле, включая установленную PWA, затем открыть GChat снова при доступной сети. Готовый waiting worker может активироваться после закрытия старых клиентов. Если новая сборка ещё не установлена, нужно дождаться её установки; она не заменяет worker при наличии открытого старого клиента без подтверждения. Удалять данные сайта, localStorage, сессию и установленную PWA для этого не требуется.

## Предлагаемое поведение

Отдельная публичная страница `/apps/recover.html` для серверного размещения и `/recover.html` для корневого доступна по прямой ссылке. Эти пути не перехватываются старым worker; новая реализация также исключает страницу и её зависимости из кеша оболочки. HTTP-ответы страницы и её зависимостей требуют `Cache-Control: no-store`. Страница загружается из сети независимо от React-приложения и его звонкового клиента.

Заголовок — «Восстановление GChat». Текст объясняет, что обновление могло зависнуть, и предлагает завершить звонки и закрыть остальные окна GChat, включая PWA. Действие — «Обновить GChat». Вызов этого действия означает явное согласие на установку текущей опубликованной Web-сборки. Автоматическая активация при открытии страницы не выполняется.

После нажатия страница ставит исключительный запрос на существующий lock `gchat-frontend-update`. Пока lock занят, она показывает «Завершите звонки и закройте остальные окна GChat». Захват не прерывается по таймауту и не обходит владельца: старое окно с ошибкой должно быть закрыто пользователем. Страница не рассылает `prepare`, чтобы повторно не запускать ошибочный shutdown старого клиента. Новые владельцы ожидают за исключительным запросом по действующим правилам обновления.

После получения lock страница проверяет регистрацию GChat с точными origin, scope и URL `sw.js` своего размещения, выполняет проверку обновления и дожидается завершения установки. Готовому waiting worker передаётся существующее сообщение `GCHAT_ACTIVATE`. После успешной активации страница переходит на `/apps/client/calls` либо `/calls`; исключительный lock удерживается до уничтожения документа при переходе. Если после успешной проверки нового waiting worker нет, выполняется возврат в приложение под текущим активным worker. Отсутствующая регистрация допускает обычный переход в приложение, которое зарегистрирует PWA штатно.

Ошибка сети, установки или активации оставляет страницу открытой с понятной ошибкой и действием «Повторить»; lock освобождается. Неподдерживаемый Web Locks API показывает инструкцию по полному закрытию окон и повторному открытию GChat. Восстановление предназначено для браузера; native runtime остаётся вне этого сценария.

Страница не читает и не изменяет сессию, device binding, подписки Web Push и пользовательские настройки. Она не удаляет регистрации worker и кеши вручную: устаревший кеш удаляется обычной успешной активацией. Поддержка и оператор могут отправить пользователю прямую ссылку; появление ссылки в уже загруженном ошибочном JS не предполагается.

## Критерии приёмки

- Оба размещения открывают страницу из сети при активном старом worker, который продолжает отдавать старую оболочку приложения.
- Открытие страницы само по себе не активирует обновление и не создаёт WSS, медиа или новый звонковый клиент.
- После явного действия незавершённый звонок и shared lock удерживают обновление; закрытие последнего старого владельца позволяет продолжить. Зависшее обновление в старом окне не обходится принудительно.
- Сценарий со старым кодом воспроизводит рекурсию, затем успешно устанавливает новую сборку через страницу после закрытия остальных окон.
- После активации загружается исправленная сборка, сессия и настройки сохраняются, старый кеш удаляется штатно. Повторное открытие страницы при актуальной сборке возвращает в приложение.
- Ошибка сети, неполный релиз и ошибка активации не удаляют рабочую сборку; повтор доступен после восстановления условий.
- Другое размещение GChat и чужие регистрации service worker не затрагиваются.
- Проверяются Chromium, целевые настольные браузеры и установленная PWA на iOS/iPadOS; результат Chromium не считается приёмкой остальных платформ.
