# Разделение ответственности оболочки Web

На первом этапе решение согласовано пользователем с уточнениями: LayoutOverlaysProvider принадлежит shared/device, данные обновляются при каждом переходе на страницу, страницы сами рисуют и настраивают шапки. Первоначальное предложение перенести шапки в layout на том этапе отклонено пользователем; действующее оформление описано в контракте оболочки.

## Мотивация и границы

AppLayout смешивал композицию интерфейса с определением раздела по pathname, доступностью пунктов меню, состоянием диагностики, правилами звонка и обработкой скролла. Ответственности разделяются между LayoutProvider в app, LayoutOverlaysProvider в shared/device и отдельными компонентами оболочки. Существующие Auth, Calls и Bootstrap остаются владельцами данных; новых транспортов и копий серверной модели нет. Первоначально шапки оставались у страниц. Последующими запросами пользователь убрал шапки названий страниц, затем общую панель с аватаром и выбрал единый белый фон; функциональная строка собеседника сохраняется. Актуальные правила принадлежат контракту оболочки ниже.

По отдельному запросу пользователя внешние отступы убраны, область страниц занимает всю ширину. Внутренние отступы содержимого и safe area сохраняются.

Действующие требования, границы и критерии приёмки принадлежат [контракту оболочки Web](README.md#общая-оболочка-и-ui-kit), [потоку данных](data-flow.md) и [React-интеграции device](device-api.md). Этот документ фиксирует принятое разделение, но не подтверждает завершение реализации или проверку на реальном iPhone.
