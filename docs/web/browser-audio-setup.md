# Выбор аудиовыхода в Web/PWA без звонка

Дата: 2026-11-18, Asia/Nicosia. Пользователь явно согласовал расширение для PWA. Требуемое поведение и критерии приёмки находятся в [аудиоконтракте device](device-api.md#выбор-и-проверка-выхода-в-webpwa-без-звонка); эта запись сохраняет основание решения.

## Основание

Пользователь повторно подтвердил: в настройках локальной iOS PWA без разговора доступен только системный выход, выбрать устройство нельзя. Исправление перечитывания кеша не закрыло этот сценарий; сведения — [WEB-UI-005](ui-bugs.md#web-ui-005--недоступная-смена-аудиовыхода-в-pwa).

При разборе дефекта browser beginSetup возвращал UNSUPPORTED, а открытие настроек только вызывало enumerateDevices. В текущих [исходниках WebKit](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/UserMediaPermissionRequestManagerProxy.cpp) computeFilteredDeviceList ограничивает speaker-устройства до wasGrantedAudioAccess для документа; [MediaDevices](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/Modules/mediastream/MediaDevices.cpp) дополнительно связывает видимость выходов с доступным microphone group. Это объясняет необходимость отдельной подготовки, но не подтверждает состав списка на телефоне пользователя или поставку конкретной версии WebKit. Ранее физически работавшая диагностическая страница также открывала и удерживала микрофон перед перечислением выходов.

## Решение и мотивировка

Существующий beginSetup расширяется браузерным адаптером с временным удержанием микрофона в AudioPreparation владельца звонков. Общая Web-панель получает реальный список после явного действия пользователя. Это использует прежние enumerateDevices/setSinkId и секундный тест без второго звонкового движка, native UI и сохранения браузерных route id между запусками.

Открытых решений для реализации согласованного объёма нет. Реализация и физическая приёмка на локальной PWA остаются отдельными результатами.
