# Поток данных и маршрутизация Web

Целевой контракт перехода на React Router Data mode с `createBrowserRouter`, RouterProvider, клиентскими `loader`/`action` и сохранением Vite. TanStack Query удаляется после миграции последнего потребителя. Framework mode, SSR, файловая генерация маршрутов и второй кеш серверных данных не вводятся. Пользователь поручил самостоятельно закрыть детали, выбирая простую и качественную реализацию.

Это требуемое поведение, а не описание готового кода. Основное дерево маршрутов переведено на один Data router; NativeBoundary больше не выполняет самостоятельную навигацию. TanStack Query удалён из приложения и lock-файла. Контакты и admin-список/карточка читаются loaders, административные изменения выполняет action, подсказки групп — resource loader через fetcher. DialogRuntime предоставляет listModel/conversationModel с сериализованным чтением после commit, подписками и отбрасыванием устаревших результатов; React не держит Query-копию истории. Общий blocker подключён в app-root: административные формы регистрируют несохранённый ввод, диалоговый Composer перед навигацией выполняет CAS flush. Link/POP/device/native используют один useBlocker; ошибка flush предлагает повтор либо явный отказ. Публичная композиция device подключена. Остальные критерии и платформенная приёмка учитываются отдельно. [D007](../architecture/decisions/D007-web-routing.md) фиксирует целевое решение; границы платформы, HTTP, native-навигации и фабрики принадлежат [API device](device-api.md). Статус accepted описывает требуемый полный объём и не подтверждает завершение всех критериев.

## Направление данных

```text
URL → loader → сервис → device.http/storage → mapping → loaderData → компонент
Форма → action → сервис → сохранение → revalidation → loaderData
Именованное событие runtime → неизменяемая актуальная модель → React
```

Loader нормализует params/query, проверяет контекст и права, обращается к сервису и возвращает модель страницы. Mapping — чистая функция. Сервис владеет бизнес-операцией; компонент отображает loaderData без копирования результата в useState. Device передаётся через типизированный контекст React Router: `deviceContext = createContext<Device>()`. Bootstrap создаёт один device на документ; `getContext` роутера возвращает новый RouterContextProvider для каждой навигации/fetcher и помещает в него тот же экземпляр device. Loader/action получает его через `context.get(deviceContext)`, без React hooks, глобального SDK, прямых обращений к nativeRuntime или замыкания device в фабрике маршрутов. Если компоненту нужен device, loader возвращает `{ device, ...модель }`, компонент читает его через useLoaderData/useRouteLoaderData. Ссылка сохраняется в памяти Data router, не сериализуется в URL/history/storage и не содержит токенов в публичных снимках.

Текущая маршрутная композиция находится в [device.ts](../../applications/web/src/app/device.ts) и [router-context.ts](../../applications/web/src/app/router-context.ts): ApplicationDevice связывает реализованные HTTP/session с существующим владельцем Auth. Полный состав публичного DeviceCore продолжает реализовываться по профильному контракту. Корневой [loader](../../applications/web/src/app/loaders.ts) возвращает тот же device для App/AuthProvider/CallsProvider; login loader возвращает его форме входа. Loaders контактов/admin используют session.run из контекста и сохраняют исходный ApiResult SDK; data разворачивает сервис фичи.

HTTP-клиент — `device.http` с интерфейсом переданного generated API-класса. Защищённый сервис использует `device.session.run((http, signal) => http.method({signal, ...args}))`; сигнал Router объединяется с сигналом сессии. Native выполняет HTTP своим сетевым стеком по [контракту транспорта](device-api.md#http-и-подмена-транспорта). Фича не выбирает платформу и не создаёт отдельный SDK.

Входящие query, path params и FormData валидируются Zod-схемами соответствующей фичи до вызова SDK. Общий reader извлекает поля запроса без приведения произвольных значений к строкам; повторяющиеся поля сохраняются как массивы и не обходят скалярные схемы. Для необязательных фильтров схема задаёт контрактные значения по умолчанию; неверный path id не отправляется в HTTP. FormData проверяется discriminated union по operation, включая метод POST, обязательные поля и допустимость типов. Ошибка схемы возвращает invalid с безопасным сообщением, сохраняет ввод и не считается неизвестным результатом изменения. Пароль не нормализуется и не попадает в тексты ошибок.

Action валидирует ввод и вызывает один сервис изменения. Form/fetcher и состояния Router отражают отправку. Успех запускает штатную ревалидацию matched loaders; shouldRevalidate отключает её только для маршрутов, не владеющих изменёнными данными, например descriptor диалога. Специальный API ручной инвалидации кеша не вводится. Такое разделение соответствует [Data mode](https://reactrouter.com/start/data/data-loading) и [actions](https://reactrouter.com/start/data/actions).

## Модели маршрутов

DTO переиспользуются из generated SDK, без ручных схем HTTP. ScopeKey — безопасный идентификатор текущего server/account/session-generation, без токена; при его смене старые данные и формы удаляются из UI.

```ts
import type { AdminUserDto, GroupDto, GroupMemberDto } from '@gchat/backend-api';

export interface CallsPageData {
  scopeKey: string;
  group: { kind: 'group'; id: string } | { kind: 'all' } | null;
  groups: GroupDto[];
  contacts: GroupMemberDto[];
}

export interface AdminUsersPageData {
  scopeKey: string;
  filters: { q: string; status: 'all' | 'active' | 'disabled'; offset: number };
  users: AdminUserDto[];
  total: number;
}

export interface AdminUserPageData {
  scopeKey: string;
  user: AdminUserDto;
}

export interface DialogsPageData {
  scopeKey: string;
  dialogId: string | null;
}

export type SettingsSection = 'microphone' | 'audio' | 'push' | 'camera' | 'geolocation' | 'files';
export interface SettingsPageData {
  section: SettingsSection;
}
export interface LoginPageData {
  serverUrl: string;
  returnTo: string;
}

export type FormResult<T> =
  | { outcome: 'saved'; value: T }
  | { outcome: 'invalid'; fields: Record<string, string> }
  | { outcome: 'failed'; message: string }
  | { outcome: 'unknown'; message: string };
```

| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/`                               | Redirect с replace на `/calls`                                                                                                                                         | Нет                                                                                                        |
| `/login`                          | LoginPageData. ServerUrl — выбранный доверенный origin. ReturnTo — проверенный внутренний адрес, по умолчанию `/calls`; после входа переход с replace                  | `serverUrl` только текущий origin, `returnTo` только допустимый внутренний маршрут без секретов            |
| `/calls`                          | CallsPageData. Группы и участники читаются через сервис контактов; для admin режим all читает все страницы активных пользователей. Маппинг даёт только id/display_name | `group`: доступный UUID группы либо `all` только для admin; отсутствующий означает первую доступную группу |

Loader обеспечивает готовность локального scope и выбранной переписки; живые данные принадлежат DialogRuntime                                         | Нет                                                                                                        |

Начальное чтение и изменения устройства приходят из сервисов device                                                           | Нет                                                                                                        |

Web-loader канонизирует некорректные необязательные фильтры к значениям по умолчанию с replace. Невалидный path id даёт 404 до HTTP. Native использует тот же normalizer, но отклоняет неизвестные параметры/невалидные значения вместо незаметной смены цели. Hash в native-командах запрещён. Query `returnTo` не принимает origin, `//`, вложенный login/returnTo, токены и пароли. Служебный query Router для index action не принимается как native-цель.

Общий protected route объявляет sessionMiddleware: она проверяет сессию через device до запуска matched loaders/actions и помещает безопасного пользователя в типизированный userContext. Тот же middleware-предок обязателен для защищённых resource/fetcher-маршрутов. Loaders/actions читают context.get(userContext), без повторного routeSession; matched loaders после middleware могут выполняться параллельно. Родительского UI RequireSession недостаточно. Административный loader проверяет роль до admin-запроса; backend guards сохраняются. При anonymous middleware перенаправляет на login с проверенным returnTo, при истечении текущей сессии старые loaderData немедленно скрываются. Loader на каждой операции передаёт request.signal; поздний ответ старого scopeKey не публикуется.

## Владение состоянием

| Данные                                       | Владелец                     | Правило                                                         |
| -------------------------------------------- | ---------------------------- | --------------------------------------------------------------- |
| Поиск, фильтр, страница, адресуемая сущность | URL                          | Временный ввод до применения фильтра допустим локально          |
| Контакты, список и карточка admin            | Router loaderData            | Нет параллельного Query-кеша или копии данных в state           |
| Производные поля                             | Mapping/чистый selector      | Не синхронизируются useEffect                                   |
| Форма до сохранения                          | Один черновик формы          | База сохранённой записи отделена от локальных изменений         |
| Меню, видимость пароля, подтверждение        | Локальный UI state           | Не становится сохранённой серверной сущностью                   |
| Сессия, звонок, соединение, устройство       | Профильный runtime за device | Живёт выше страниц, предоставляет типизированные enum-события   |
| История, outbox, постоянный черновик диалога | DialogRuntime/storage        | Сохраняются scope/CAS/epoch и согласование вкладок по Bootstrap |

Контакты не копируются в состояние звонкового движка. Текущее имя собеседника — selector по странице/справочнику, имя вне загруженной страницы разрешает сервис контактов с дедупликацией одновременного чтения в рамках одной загрузки. Постоянный кеш контактов и имён не вводится; временный справочник долгоживущего UI очищается при смене scope и заменяется целиком актуальной моделью, без второго владельца серверных сущностей.

## Живые модели диалогов

Диалог не поддерживается одновременно изменяемыми копиями в loaderData и runtime. Loader возвращает descriptor; доступная локальная история показывается сразу, сетевое обновление выполняет runtime. Ошибка сети не блокирует чтение локальной истории. Новая переписка без локальных данных показывает явное состояние загрузки/ошибки.

Runtime предоставляет `listModel()` и `conversationModel(dialogId)` — стабильные источники с getState и on(enum, handler). Снимки неизменяемые, кешируются по storage revision после commit и не перечитываются из IndexedDB/SQLite при каждом React-render. Существующий getSnapshot только со служебным статусом расширяется адаптером модели; Query-инвалидация больше не нужна.

```ts
import type { DialogDto } from '@gchat/backend-api';
import type { DialogView } from '../../shared/dialogs/runtime';

export enum DialogModelEvent {
  ListChanged = 'listChanged',
  ConversationChanged = 'conversationChanged',
}
export interface DialogListState {
  revision: number;
  status: 'starting' | 'ready' | 'error';
  items: readonly DialogDto[];
  hasMore: boolean;
  error: string | null;
  storageWarning: string | null;
}
export interface DialogConversationState {
  revision: number;
  dialogId: string;
  status: 'starting' | 'ready' | 'error';
  view: Readonly<DialogView> | null;
  error: string | null;
}
export interface DialogModel<T, E extends DialogModelEvent> {
  getState(): Promise<T>;
  on(event: E, handler: (state: T) => void): () => void;
}
export interface DialogModels {
  listModel(): DialogModel<DialogListState, DialogModelEvent.ListChanged>;
  conversationModel(
    id: string,
  ): DialogModel<DialogConversationState, DialogModelEvent.ConversationChanged>;
}
```

Снимок view включает уже определённые record/messages/outbox/draft/syncing; новая серверная схема не создаётся. Адаптер перечитывает только изменившийся диалог после storage commit и отбрасывает результат меньшей revision/старого scope. Событие метаданных/непрочитанности обновляет список; сообщение, outbox и черновик — выбранную conversationModel и затронутую строку списка. Служебный статус не вызывает полную ревалидацию всех маршрутов. Пагинация/older остаются у runtime; loader не становится вторым владельцем соединения или истории. Модели не накапливают всю историю: conversation-кеш освобождается после последней подписки и завершения связанных операций; сохранённые данные остаются в storage. Новый scope создаёт новые источники, старые ответы не публикуются.

## Формы, конфликты и неизвестный результат

Черновик административной формы инициализируется при открытии сущности и хранит baseSnapshot, values и dirty. При чистой форме новая loader-модель заменяет базу. При dirty новая модель не затирает values: если изменились редактируемые поля базы, UI предлагает загрузить новые значения или оставить ввод. Серверного compare-and-swap, которого нет в API, клиент не обещает. При смене userId создаётся новый черновик после прохождения blocker. Пароль живёт только в памяти формы, без URL, loaderData или постоянного storage.

Actions создания, смены пароля и доступа возвращают FormResult. Saved отражается через ревалидацию; failed/invalid/unknown сохраняют ввод. Повторная отправка блокируется на время операции. Сеть, некорректный успешный ответ и 5xx не дают основания повторить изменение; unknown требует сверить актуальные данные и нового явного нажатия. Чтение карточки не подтверждает установку конкретного пароля. Однократный показ выданных credentials сохраняет действующий контракт, включая собственный сброс пароля и скрытие при background.

Диалоговый черновик сохраняется через существующий CAS runtime, без второй React-копии сохранённого текста. Локальный буфер печати имеет revision базы, сохраняется по существующим правилам и сбрасывается только после подтверждённого commit. Перед уходом flush завершается, затем навигация продолжается. Ошибка flush блокирует уход и предлагает повтор либо явный отказ от несохранённого ввода; обязательная инвалидация сессии сохраняет правила Bootstrap и не продолжает запросы старого namespace.

Один [blocker в app-root](../../applications/web/src/shared/navigation-protection.tsx) объединяет dirty-состояние форм. Он охватывает Link, Browser Back/Forward, программную и native-навигацию через общий Router; используется [useBlocker](https://reactrouter.com/api/hooks/useBlocker). Подтверждение не дублируется отдельным native-dialog. При жёсткой перезагрузке применяется beforeunload: гарантии записи после закрытия вкладки не обещаются. Смена подтверждённо недействительной сессии обходит blocker и удаляет обычные пользовательские данные из UI. Открытые формы, mutations в sessionMiddleware и однократный показ credentials удерживают общий shared update lease документа; операция заимствует уже удерживаемый lock, чтобы не попасть за ожидающим exclusive updater. Lease действия живёт независимо от страницы и освобождается после публикации результата; показ credentials принимает его до освобождения действия. Черновики диалогов продолжают использовать собственный flush lease runtime. Новая форма, открытая после начала обновления и ещё не получившая shared lock, недоступна для ввода до безопасного завершения обновления.

## Композиция и переход

Bootstrap создаёт device, передаёт конфигурацию маршрутов/normalizer и инициализирует его типизированный контекст React Router. Навигационный адаптер создаёт один router вне React state и владеет им; DeviceProvider монтирует RouterProvider. Прямого вызова реализации router из bootstrap/native-подписки нет. Сервисы сессии, Calls и DialogRuntime живут выше страниц и не пересоздаются при смене URL.

Операции с user activation — микрофон перед звонком, разрешения, выбор файлов/выхода, разблокировка звука — вызываются из обработчика жеста напрямую через device. Их не переносят в отложенный action, который потеряет жест. Обычные сохранения admin-форм принадлежат actions; отправка/черновики диалога — существующему runtime/outbox.

Порядок миграции:

1. Собрать device и router, передать зависимости существующим сервисам, сохранить один WSS и владельца медиа.
2. Перенести контакты и admin-списки/карточки в loaders, административные сохранения в actions; удалить их query hooks и синхронизирующие эффекты.
3. Подключить живые модели Calls/Dialogs/Device и единый blocker. Удалить Query-инвалидации диалогов и копии контактов в CallsProvider.
4. После последнего потребителя удалить QueryClientProvider, query helpers и зависимость TanStack Query. Промежуточный этап не объявляется завершённой миграцией.

## Ленивые модули и вложенные маршруты

Расширение согласовано пользователем 2026-11-08, включая использование вложенных маршрутов.

Используется `route.lazy` в существующем Data mode. Определение дерева (`id`, `path`, `index`, `children`) остаётся статическим для синхронного сопоставления URL и native-нормализации. Модули входа, контактов, диалогов, настроек и администрирования подключаются динамическими import при первом обращении к соответствующему маршруту. Существующий PWA precache assets сохраняется: фоновое скачивание chunks сервис-воркером не означает их импорт и выполнение в документе. Resource-маршрут подсказок групп загружает только свой обработчик.

Для настроек каждый адресуемый экран имеет отдельную точку динамического импорта: корень, список «Основные», микрофон, звук, push, камера, геопозиция и файлы. Корень не импортирует список «Основные» или реализации секций; список не импортирует экраны секций. Общие UI-компоненты и подписка на состояние устройства могут переиспользоваться, но не должны транзитивно включать код всех страниц. Проверка состава сборки и браузерная регрессия подтверждают эти границы.

Список диалогов, пустой index и выбранная переписка имеют отдельные route.lazy-модули. Список не импортирует Room/Feed, Composer, виртуализатор или UI стикеров; редактор и отображение сообщений подключаются только с перепиской. Чистое форматирование может быть общим.

В разделе звонков контакты, карточка выбранного собеседника, карточка текущего вызова и диагностика имеют отдельные модули. Для существующих условных панелей без собственного URL применяется React.lazy/Suspense; новые адреса не вводятся. Карточка вызова не импортируется статически через глобальный входящий экран. Его лёгкий контейнер остаётся доступен во всех разделах; на время загрузки или при ошибке модуля сохраняются базовые действия принятия/отклонения/завершения через существующий runtime. Ошибка панели не размонтирует владельцев сессии/звонка. Вызов call.prepareOutgoing и другие операции с user activation происходят из обработчика явного нажатия, без предварительного await import; загрузка UI сама не начинает и не повторяет звонок. CallsProvider и звонковый клиент остаются долгоживущими. Проверки импортов, прямой ссылки переписки, сохранения списка, исходящего/входящего вызова и диагностики подтверждают эти границы.

UI и обработчики данных имеют отдельные точки импорта: object-form lazy для Component и loader/action позволяет загружать их параллельно. Общие небольшие обработчики bootstrap и sessionMiddleware остаются статическими. Middleware сохраняет защиту всей ветки, а обработчики сохраняют проверки роли и session scope. Динамический импорт не является проверкой доступа.

Оболочка, владельцы сессии, звонков, входящих вызовов и device остаются выше ленивых страниц. Статические импорты из оболочки не должны транзитивно включать страницы разделов в начальную сборку. Общий показ однократных credentials сохраняет действующее время жизни результата и правила скрытия; экран UsersPage выделяется из App в модуль административного маршрута.

Переходы отражаются через useNavigation, отправки форм — через состояние fetcher/Form. Во время загрузки следующего маршрута оболочка и текущий звонок сохраняются. Маршрутные ErrorBoundary обрабатывают ошибки loader/action и загрузки модулей; для ошибки импорта дочернего модуля доступна уже загруженная родительская граница. Сообщения не раскрывают секреты; восстановление не повторяет action автоматически и не перезагружает документ без явного действия пользователя. Корневая граница остаётся последней защитой.

Вложенность отражает композицию UI: оболочка раздела рендерит Outlet, index задаёт начальный экран. В диалогах список остаётся родительским layout, выбранная переписка — дочерний маршрут :dialogId; пустой выбор — index. В администрировании список остаётся родителем карточки :userId, карточка рендерится в Outlet и получает callbacks операций через типизированный outlet context. Настройки имеют явные вложенные general и маршруты секций вместо разбора pathname внутри страницы; неизвестная секция сохраняет экран отсутствующей настройки. URL и правила native-нормализации не меняются. Смена дочернего маршрута не размонтирует родительский список.

Критерии приёмки расширения:

- Сборка выделяет страницы разделов в динамические chunks; не посещённые разделы не загружаются статическими импортами оболочки. Общие зависимости и долгоживущие runtime могут оставаться в начальной сборке.
- Прямой URL, переход Link, POP и native-навигация работают при первом и повторном открытии ленивого раздела; сохраняются route id, basename, loaderData и доступы.
- Загрузка UI и обработчика не образует искусственную последовательность импортов; отмена навигации и смена сессии сохраняют существующие гарантии данных.
- Ошибка загрузки модуля или loader/action отображается доступной границей, не останавливает звонок и не вызывает автоматического повторения изменения.
- Web typecheck/build, относящиеся маршрутные тесты и проверка состава сборки подтверждают поведение. Платформенная приёмка учитывается отдельно.

API и ограничения Data mode: [Route Object](https://reactrouter.com/start/data/route-object) и [Custom Framework / lazy loading](https://reactrouter.com/start/data/custom).

## Критерии приёмки

- Прямой URL, Web/native-переход и история дают одну модель страницы. Сохраняются basename, SPA fallback, доступы и форма адреса из Web-контракта.
- Protected loaders/actions независимо проверяют готовую сессию/роль; отменённые и старые scope не публикуют данные. Токены не попадают в URL/loaderData/history.
- У сохранённой сущности один владелец. Нет Query-кеша поверх loaderData или DialogRuntime, нет копирования loaderData в отображающий state.
- Saved ревалидирует затронутые данные; dirty-форма не теряет ввод при фоновом обновлении. Unknown не повторяет изменение автоматически.
- Диалоги обновляются из commit-событий без повторного чтения storage на каждый render и ревалидации всего router. Сохраняются локальная история, CAS, outbox, порядок и ограничения отправок Bootstrap.
- Link/POP/native одинаково защищают несохранённый ввод. Инвалидация сессии скрывает старые данные и не блокируется формой.
- Смена страницы не останавливает WSS, выбранный звонок и удерживаемую им камеру; не появляется второй runtime/refresh/capture.
- User activation и межвкладочная координация сохраняются. Завершение миграции проверяется отсутствием query hooks/provider/зависимости.
- Для реализации выполняются Web typecheck/build и относящиеся unit/маршрутные E2E. Физические аудио/iOS/PiP/push проверки учитываются отдельно. Для документации — `pnpm docs:check` и проверка TypeScript-примеров.

В принятом объёме документа открытых архитектурных решений нет. Расширение backend API, новые продуктовые функции и платформенная приёмка ведутся у профильных владельцев и не считаются выполненными этой спецификацией.
