# Внутренний клиент HTTP API backend

Внутренний workspace-пакет `@gchat/backend-api` генерирует JavaScript-клиент из OpenAPI backend. Он работает в браузере и Node.js, поставляет ESM, CommonJS и декларации TypeScript. Runtime-зависимостей, React, TanStack Query и runtime-валидации DTO нет. Пакет приватный, публикация в npm не требуется.

## Назначение и границы

Пакет убирает ручное дублирование HTTP-маршрутов, параметров и DTO. Генерируются все операции текущей спецификации, включая Auth, Groups, Backoffice и healthcheck. Devices и DirectCalls попадут в SDK, когда соответствующие HTTP-операции появятся в экспортируемом документе. Наличие административного метода не даёт прав на его выполнение: доступ проверяет backend.

WebSocket-протокол, WebRTC, управление звонком, UI и Swift-клиент не входят в пакет. Получение WS-билета — обычная HTTP-операция. Хранение сессии, JWT, refresh, координация вкладок и device binding остаются в приложении по [Auth](../backend/modules/auth.md) и [веб-контракту](../web/README.md).

Веб-клиент использует SDK для всех HTTP-операций. Его [auth.ts](../../applications/web/src/auth.ts) управляет сессией и вызывает типизированные методы через общий callback; маршруты и HTTP DTO в приложении не дублируются. Библиотека не импортирует backend DTO, NestJS, браузерное хранилище или Node.js-модули во время выполнения.

## Источник контракта и генерация

Источником служит документ конкретной ревизии backend, сформированный после сборки со Swagger-плагином. Требуемое поведение HTTP принадлежит профильным backend-контрактам, реализованная схема — контроллерам и DTO. Расхождения исправляются у владельца схемы; ручные правки сгенерированных типов и методов запрещены.

[Автономный экспорт](../backend/openapi.md#автономный-экспорт-для-генерации-клиента) не запускает HTTP-сервер и не требует PostgreSQL, Redis, APNs или production-секретов. Настройки документа общие с HTTP-приложением. Экспортёр обнаруживает скомпилированные контроллеры, подменяет их зависимости и guards; `AppModule` не загружается. Проверка сравнивает результат с документом полноценного `AppModule` той же сборки с тестовыми инфраструктурными зависимостями. Контроллеры должны находиться в `*.controller.ts`, DTO — в `*.dto.ts`.

Генератор — Hey API (`@hey-api/openapi-ts`), точная версия закреплена в [манифесте](../../packages/backend-api/package.json) и lock-файле. Он генерирует типы DTO, аргументов и ответов операций. Дополнительный emitter в [generate.mjs](../../packages/backend-api/scripts/generate.mjs) использует эти типы и OpenAPI для генерации класса `BackendApi`. Ручного списка маршрутов и обёрток отдельных endpoints нет. Общий транспорт и обработка ошибок поддерживаются вручную.

Перед генерацией проверяются OpenAPI через Swagger Parser, локальные ссылки, уникальные явные `operationId`, параметры, тела и успешные ответы. Поддержаны JSON-тела и ответы, скалярные path-параметры с `simple`, скалярные и массивные query-параметры с `form`. Неизвестная сериализация или схема авторизации вызывает ошибку генерации, а не произвольное преобразование данных. Runtime-валидаторы не генерируются.

Имена методов совпадают со стабильными явными `operationId` по [политике backend](../backend/openapi.md#имена-операций-operationid). Переименование контроллера или его метода при сохранении идентификатора не меняет SDK.

## Публичный API

Публичная точка входа `@gchat/backend-api` экспортирует именованный класс `BackendApi`, типы операций и DTO, `ApiResult<T>`, `BackendApiOptions`, `ApiError` и `ApiResponseParseError`. Операции доступны методами одного экземпляра без группировки по контроллерам.

```ts
import { BackendApi } from '@gchat/backend-api';

const api = new BackendApi({
  baseUrl: '/api',
  getAccessToken: () => sessionStore.accessToken,
});

const result = await api.adminListUsers({ query: { q: 'ivan' } });
console.log(result.data, result.status, result.headers);
```

| Настройка        | Контракт                                                                                                                                                                            |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseUrl`        | Обязательный адрес API. Браузер допускает относительный `/api` и абсолютный URL; Node.js с обычным Fetch требует абсолютный URL. Базовый путь сохраняется.                          |
| `fetch`          | Необязательный транспорт с контрактом Fetch API; по умолчанию используется транспорт среды.                                                                                         |
| `getAccessToken` | Синхронный или асинхронный поставщик актуального токена либо `null`/`undefined`. Вызывается перед каждой защищённой операцией. Публичные операции автоматически Bearer не получают. |

Экземпляры изолированы: base URL, транспорт и токены одного клиента не влияют на другой. Изменяемого глобального singleton нет.

Каждый метод принимает один объект с применимыми секциями `path`, `query`, `body` и необязательным `signal: AbortSignal`. Секции с обязательными параметрами обязательны в TypeScript; если обязательных аргументов нет, объект можно опустить. URL и HTTP-метод не передаются вызывающим кодом.

JSON-поля сохраняют имена, включая `snake_case`. Необязательность отличается от `null`; даты остаются строками. Path/query кодируются, тело сериализуется в JSON. Успех возвращает `Promise<ApiResult<T>>`:

```ts
export type ApiResult<T> = {
  data: T;
  status: number;
  headers: Headers;
};
```

`T` определяется успешными ответами OpenAPI; для ответа без тела используется `undefined`. Ответ `204` не разбирается как JSON. Статические типы не гарантируют соответствия фактического JSON серверной схеме: пакет не проверяет DTO, обязательность полей, enum и ограничения во время выполнения.

## Авторизация и повторы

Bearer определяется `security` в OpenAPI. Ошибочное описание защищённости исправляется в backend, а не списком маршрутов в SDK. Клиент не проверяет административные права локально и не заменяет guards.

Login/refresh/logout выполняют только соответствующий запрос. Пакет не хранит токены, не обновляет их на `401` и не повторяет запросы. Приложение решает, допустим ли повтор; в частности, формирует и сохраняет `request_id` для refresh. SDK не меняет его. Ошибка сети, отмена или `503` не гарантируют, что сервер не выполнил действие.

## Ошибки

Любой HTTP-ответ вне 200–299 выбрасывает `ApiError`, наследующий `Error`. Он сохраняет `status`, `headers`, разобранное `body`, а для стандартной [оболочки ошибок](../backend/modules/errors.md) — строковый `code`, безопасное сообщение и `fields`. Неизвестные коды сохраняются. Доступен `Retry-After`; клиент сам не ждёт и не повторяет запрос.

HTTP-ошибка без стандартной оболочки, включая readiness `503`, сохраняет статус и тело как неизвестное значение. Не-JSON тело ошибки сохраняется текстом. Некорректный JSON при HTTP-отказе сохраняет статус и заголовки в `ApiError`, исходную причину — в `cause`; тело недоступно. Некорректный JSON успешного ответа выбрасывает `ApiResponseParseError` с `status`, `headers` и исходной причиной в `cause`.

Сетевые ошибки и отмена, включая ошибку чтения потока ответа, пробрасываются без обёртки. SDK не придумывает backend-коды и не пишет в логи запросы, пароли, токены, WS-билеты или конфигурацию транспорта.

## Подключение, сборка и обновление

Потребитель подключает пакет через `workspace:*` и использует публичную точку входа. Сначала собирается пакет; обычная сборка не запускает экспорт OpenAPI, сборку backend или внешние сервисы:

```sh
pnpm --filter @gchat/backend-api build
pnpm --filter @gchat/backend-api typecheck
pnpm --filter @gchat/backend-api test
```

ESM использует `import`, CommonJS — `require`; `exports` направляет обе формы к своим JavaScript и декларациям. Потребитель не компилирует TypeScript библиотеки. `dist` в Git не хранится. Node.js соответствует корневому манифесту и `.nvmrc`; браузерная сборка рассчитана на Chrome 104+, Firefox 102+, Safari 16.4+ с Fetch API. Отдельная script-tag сборка не поставляется.

При изменении HTTP-контракта из корня:

```sh
pnpm api:generate
pnpm api:check
pnpm --filter @gchat/backend openapi:test
pnpm docs:check
```

`api:generate` собирает backend, экспортирует `packages/backend-api/openapi.json` и генерирует `src/generated/`. Эти артефакты хранятся в Git. Генерация пакета отдельно (`pnpm --filter @gchat/backend-api generate`) читает только локальный снимок, не обращается к развёрнутому серверу. Перед удалением операции или изменением сигнатуры проверяются потребители.

`src/generated/provenance.json` хранит SHA-256 входной схемы и ревизию исходников backend по содержимому: SHA-256 отсортированных имён и содержимого контроллеров, DTO, Swagger и конфигурации компиляции. Это не Git commit SHA. Посторонние коммиты, timestamps и случайные значения не меняют результат генерации.

`api:check` собирает backend, экспортирует схему и повторяет генерацию во временном каталоге. Сравниваются схема, содержимое и полный набор сгенерированных файлов, включая добавления и удаления. Репозиторий не обновляется; несовпадение завершает проверку с ошибкой. CI запускает эту проверку, сверку документов одной сборки и тесты пакета.

## Проверки

Тесты пакета проверяют ESM/CommonJS и разрешение деклараций, обязательные аргументы и отсутствие лишних секций, path/query, JSON, nullable-поля, `204`, относительный и абсолютный базовый путь, Bearer, смену токена и изоляцию клиентов. Проверены HTTP-ошибки, неизвестные коды, `fields`, `Retry-After`, нестандартные тела, некорректный JSON, отмена и сетевые ошибки без повторов. Браузерный smoke-тест собирает пакет с browser target и выполняет запрос в окружении без Node.js globals. Это не тест в настоящем браузере.

Тест из сборки backend сравнивает автономную схему с документом `AppModule`, проверяет административные DTO, nullable и публичный healthcheck. Отдельные тесты HTTP-приложения сохраняются в backend. Проверки интеграции SDK с браузерной сессией находятся в веб-приложении, системные сценарии — в общем E2E-пакете.
